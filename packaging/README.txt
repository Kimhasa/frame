FRAME Console 0.5.0

실행
FrameConsole.exe를 실행합니다. 왼쪽 메뉴의 "송출 하기"에서 내 화면을 보내고, "전체 수신 목록"에서 다른 PC의 방송을 봅니다.
FFmpeg와 MediaMTX는 프로그램이 직접 실행하고 종료합니다. 별도로 실행하지 마세요. 실행만으로 송출하거나 마이크를 녹음하지 않습니다.
폴더 위치에 공백이나 한글이 있어도 됩니다. 폴더 안의 파일 구성을 유지하세요.

송출
1. "대상 변경"(처음에는 대상 선택)에서 "프로그램 창" 또는 "전체 화면"(모니터)을 고릅니다. 모니터는 왼쪽부터 번호가 붙고
   실제 화면 썸네일, 해상도, 배율, 주 모니터 여부가 표시됩니다.
2. "송출 설정"에서 화질, 프레임 속도, 오디오(사용 안 함/시스템 오디오/마이크/시스템 + 마이크)를 고르고 시청 주소를 확인합니다.
   "연결 설정"에서는 서버 주소, 스트림 ID, 포트를 바꿉니다.
3. "송출 시작"을 누릅니다. 방송마다 고유 ID가 만들어지고, 같은 내부망의 FRAME Console 목록에 자동으로 나타납니다.
송출 중에는 오른쪽 "실시간 채팅"으로 시청자와 대화할 수 있습니다. 송출 중에는 이 PC가 절전 모드로 들어가거나 화면이 꺼지지 않게
Windows에 요청합니다(설정은 바꾸지 않으며 송출이 끝나면 해제합니다).

화질과 비트레이트
송출 해상도는 선택한 화질 그대로입니다(1080p = 1920×1080). 공유한 창·모니터의 내용은 원본 비율을 유지한 채 출력 화면에 맞게
확대·축소해 가운데 배치합니다. 비율이 다르면 그만큼 여백이 생깁니다(예: 세로로 긴 창은 좌우 여백). 내용을 늘리거나 잘라 여백을 없애지 않습니다.
송출 중 창 크기를 바꿔도 출력 해상도는 그대로이며 내용 배치만 다시 계산합니다(이벤트 기록에 표시). 송출 미리보기는 실제 송출과 같은 배치를 보여줍니다.
비트레이트 자동은 송출 해상도, FPS, 인코더를 기준으로 계산합니다: 0.07 bit/픽셀(60fps 기준) × (FPS/60)^0.75, libx264는 0.85배.
기본 방식은 "품질 우선 가변(VBR)"이며 비트레이트 값은 상한입니다(NVENC: -rc vbr -cq 23, libx264: -crf 23, 둘 다 상한 적용).
정지된 글자 화면은 상한보다 훨씬 적게, 움직임이 많은 화면은 상한까지 씁니다. 고정 비트레이트가 필요하면 설정 파일의 rateControl을 "cbr"로 바꿉니다.
Intel QSV와 AMD AMF는 고정 비트레이트로 동작합니다. 직접 입력한 비트레이트, 해상도, FPS는 프로그램이 몰래 바꾸지 않습니다.

다른 PC에서 시청
전체 수신 목록: 같은 내부망(같은 서브넷)의 FRAME Console 방송이 자동으로 표시됩니다. 카드를 누르면 바로 재생합니다.
수동 연결: 목록의 "수동 연결"에 송출 PC 주소, 스트림 ID, 포트를 넣습니다.
브라우저: FRAME Console이 없는 PC는 Chrome 또는 Edge로 송출 화면의 시청 주소(예: http://192.168.1.27:8889/screen-01)를 엽니다.
  http://송출PC주소:8889/ 를 열면 그 PC가 아는 방송 목록이 나옵니다.
시청 페이지는 영상 수신과 채팅만 할 수 있고 송출 시작/중지 같은 송출 PC의 기능은 호출할 수 없습니다.

재생 화면
하단 조작부(재생바, 시간, 일시정지, 음량, 실시간, 화질, PiP, 확대 보기, 전체 화면)와 그라데이션은 재생 중 숨겨집니다. 영상 위에서 마우스를 움직이면
나타나고, 약 2.5초간 움직임이 없거나 영상 밖으로 나가면 사라집니다. 일시정지 중, 조작부 위에 포인터가 있을 때, 재생바·음량을 끄는 동안, 화질 메뉴가
열려 있을 때, Tab 등 키보드로 조작부에 있을 때는 계속 보입니다. 터치 화면에서는 한 번 탭하면 조작부만 나타나고(재생은 그대로), 보이는 상태에서
영상을 탭하면 일시정지·재생합니다. 숨은 조작부는 클릭을 받지 않으며 플레이어 크기는 변하지 않습니다. 브라우저의 PiP 창 조작부는 브라우저가 관리합니다.
플레이어 틀은 화면 배치를 따르고 영상은 그 안에서 비율을 유지해 표시합니다(틀과 영상 비율이 다르면 위아래 또는 좌우 여백).

재생과 되감기(DVR)
재생바로 현재 방송을 처음부터 최신 시점까지 이동할 수 있습니다. 최근 몇 분으로 제한하지 않습니다. 늦게 들어온 시청자도 처음 부분을 볼 수 있습니다.
"실시간" 버튼은 지난 구간 재생을 끝내고 실시간 영상으로 돌아갑니다. 지난 구간을 보는 동안에는 실시간 영상 연결을 닫아 소리가 겹치지 않습니다.
실시간 화면을 3초 넘게 일시정지했다가 다시 재생하면 멈춘 지점부터 녹화본으로 이어 봅니다. 바로 실시간으로 가려면 "실시간"을 누릅니다.
재생 위치는 시청자마다 따로이며, 한 시청자의 되감기는 송출이나 다른 시청자에게 영향을 주지 않습니다.
녹화는 원본 화질만 저장합니다. 낮은 재생 화질(720p 등)은 실시간 시청 전용이고, 지난 구간은 원본 화질로 재생합니다.
최신 녹화 시점은 실시간보다 약 1초 늦습니다(1초 단위로 디스크에 기록). 재생 가능한 끝까지만 재생바에 표시합니다.
녹화가 멈췄던 구간(디스크 부족 등)은 재생바에서 건너뛰고 다음 녹화 구간부터 이어 재생합니다.
되감기는 Media Source Extensions를 지원하는 브라우저가 필요합니다(PC의 Chrome, Edge, WebView2에서 확인). 지원하지 않는 브라우저
(예: iPhone Safari)에서는 재생바가 숨겨지고 실시간 시청만 됩니다.
방송이 끝나면 그 방송의 되감기도 끝납니다. 녹화 파일은 보관 정책에 따라 남습니다(아래 "녹화 저장").

녹화 저장
송출을 시작하면 MediaMTX가 FFmpeg가 이미 인코딩한 영상을 다시 인코딩하지 않고 그대로 저장합니다(fMP4, 60초 단위 파일).
위치: %LOCALAPPDATA%\FrameConsole\recordings\<방송 ID>\<스트림 ID>\날짜_시각.mp4, 방송 정보는 <방송 ID>\broadcast.json
(크기, 평균 비트레이트, 인코더, 시작/종료 시각). 프로그램 폴더가 OneDrive 같은 동기화 폴더일 수 있어 기본 위치를 로컬 폴더로 둡니다.
각 파일은 일반 동영상 재생기로도 열 수 있습니다.
설정 파일(config\frame-console.json):
  recordEnabled    false면 녹화하지 않습니다(되감기 없이 실시간만).
  recordDir        녹화 폴더. 비우면 위 기본 위치. 상대 경로는 프로그램 폴더 기준.
  recordMaxGB      이 프로그램이 만든 녹화 전체의 상한(기본 200). 넘으면 끝난 방송 중 오래된 것부터 지웁니다.
                   현재 방송만으로 넘으면 녹화를 멈추고(라이브는 계속) 이벤트 기록에 알립니다.
  recordMinFreeGB  녹화 디스크의 최소 여유 공간(기본 5). 부족하면 녹화를 멈추고 라이브는 계속합니다.
                   여유 공간이 2 GB 이상 회복되면 녹화를 다시 시작합니다. 멈춘 구간은 되감을 수 없습니다.
  recordKeepDays   끝난 방송을 보관할 일수(기본 7, 0은 기간 제한 없음). 송출을 시작할 때 지난 방송을 정리합니다.
현재 방송의 앞부분은 방송 중에 지우지 않습니다. 정리 대상은 이 프로그램이 만든 방송 폴더(방송 ID 이름 + broadcast.json)뿐이며,
recordDir에 다른 파일이 있어도 지우거나 용량에 포함하지 않습니다.
녹화 시작, 멈춤, 재개, 종료 시 크기와 평균 비트레이트는 송출 화면의 동작 기록에 표시됩니다.

채팅
방송마다 별도의 채팅방이 있고 새 방송은 새 방에서 시작합니다. 수신 화면에서는 채팅이 기본으로 열립니다.
"이름 설정"에서 표시 이름을 정합니다: 1~20자, 앞뒤와 연속 공백 정리, 제어 문자 불가, "시스템/관리자/admin/system/administrator" 불가,
다른 PC가 쓰는 이름은 사용할 수 없습니다(같은 PC의 송출 채팅과 수신 채팅은 같은 이름을 쓸 수 있음). 서버가 확정한 이름이 표시됩니다.
Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 전송하지 않습니다. 메시지는 1000자까지, 10초에 8개까지 보낼 수 있습니다.
메시지는 서버가 확인한 뒤에만 표시되고, 입력한 내용은 글자로만 표시됩니다(HTML로 해석하지 않음). 늦게 들어오면 최근 100개를 받습니다.
지난 구간을 보는 동안에도 채팅은 현재 방송의 실시간 대화입니다. 채팅 연결이 끊겨도 영상은 계속되며 채팅은 자동으로 다시 연결합니다.

필요한 환경
Windows 10 버전 2004(빌드 19041) 이상 또는 Windows 11, x64.
Microsoft Edge WebView2 Runtime. Windows 11에는 기본 설치되어 있습니다. 없으면 실행 시 안내가 나오며
redist\MicrosoftEdgeWebView2RuntimeInstallerX64.exe(인터넷 없이 설치되는 공식 설치 파일)를 실행하면 됩니다.
관리자 권한 없이 실행하면 현재 사용자용으로 설치됩니다. 고정 버전 런타임을 쓰려면 runtime\webview2 폴더에
Fixed Version Runtime을 풀어 두세요. 그 폴더가 있으면 우선 사용합니다.
Visual C++ 재배포 패키지는 필요 없습니다. 실행 PC에 인터넷, npm, Node, Python, 개발 도구가 필요하지 않습니다.

방화벽과 포트
다른 PC가 접속하고 목록에 표시되려면 송출 PC에서 다음 수신을 허용해야 합니다.
  TCP 8889 FrameConsole.exe   시청 페이지, 방송 목록, 썸네일, 되감기 구간, 채팅, WebRTC 연결 요청(WHEP)
  UDP 8899 FrameConsole.exe   같은 서브넷의 방송 목록 알림(멀티캐스트 239.255.42.99)
  UDP 8189 bin\mediamtx.exe   WebRTC 영상/음성
  TCP 8189 bin\mediamtx.exe   UDP가 막힌 경우의 WebRTC 대체 경로
처음 실행·송출할 때 Windows 보안 경고가 나오면 개인 네트워크에서 허용을 선택하세요. 프로그램은 방화벽 설정을 직접 바꾸지 않습니다.
경고 창을 취소하면 Windows가 차단 규칙을 만들고, 차단 규칙은 허용 규칙보다 우선합니다.
네트워크가 공용(Public)으로 설정되어 있으면 개인 네트워크 허용만으로는 접속되지 않습니다. 내부망은 개인 네트워크로 두는 것을 권장합니다.
일반 사용자가 허용할 수 없거나 차단 규칙이 생긴 경우 관리자가 tools\firewall-rules.ps1의 내용을 확인한 뒤 실행합니다
(-RemoveBlockRules: 차단 규칙 삭제, -Profile Any: 공용 네트워크 포함).
송출 포트(8554, RTSP)와 MediaMTX의 관리·녹화 재생 포트는 이 PC 안(127.0.0.1)에서만 열립니다.
외부 STUN/TURN 서버는 쓰지 않습니다. 같은 내부망에서는 필요하지 않습니다. 다른 대역 간 중계가 필요하면
config\frame-console.json의 iceServers에 내부 TURN 서버를 적습니다.

다른 서브넷의 목록
멀티캐스트 알림은 보통 같은 서브넷 안에서만 전달됩니다. 서브넷이 다르면 한 PC를 목록 수집 PC로 정하고, 각 송출 PC의
directoryServers에 그 PC의 "주소:시청포트"(예: ["10.0.0.5:8889"])를 적습니다. 송출 PC는 자기 방송을 그 PC에 HTTP로 알리고,
수집 PC의 목록(http://10.0.0.5:8889/)에 표시됩니다. 알림은 송출 PC 자신의 주소로만 등록할 수 있고 7초 동안 소식이 없으면 목록에서 빠집니다.

설정 파일
config\frame-console.json 송출을 시작할 때 화면의 설정이 저장됩니다. 예시는 config\frame-console.example.json입니다.
  serverHost       시청 PC가 접속할 이 PC의 주소. "auto"는 실행할 때 내부망 IPv4 주소를 찾습니다. 이 PC의 주소여야 합니다
                   (이 프로그램은 내장 서버로 송출하며, 다른 PC에서 실행 중인 별도 MediaMTX 서버로 보내는 기능은 없습니다).
  streamPath       스트림 ID(시청 주소의 마지막 부분)
  publishPort      FFmpeg가 MediaMTX로 보내는 RTSP 포트(이 PC 안에서만 사용)
  viewerPort       시청 페이지, 목록, 채팅, WHEP 포트
  iceUdpPort, iceTcpPort  WebRTC 미디어 포트(iceTcpPort 0은 사용 안 함)
  resolution, fps, bitrateAuto, bitrateMbps  화질, 프레임, 비트레이트(자동이면 송출 크기에 맞춰 계산)
  rateControl      vbr(기본, 비트레이트는 상한) 또는 cbr
  audio            none, system, mic, mix
  systemVolume, micVolume  송출 음량(0~100)
  audioBitrateKbps Opus 비트레이트
  encoder          auto, h264_nvenc, h264_qsv, h264_amf, libx264
  renditions       true면 시청자가 낮은 화질을 고를 때 해당 화질을 그때 인코딩합니다.
  captureCursor    마우스 포인터 포함 여부
  iceServers       내부 STUN/TURN 목록(선택)
  broadcastTitle   목록에 보일 방송 제목(비우면 공유한 창 제목 또는 모니터 이름)
  publisherName    목록에 보일 송출자 이름(비우면 PC 이름)
  discoveryPort    목록 알림 UDP 포트(0은 사용 안 함)
  directoryServers 다른 서브넷의 목록 수집 PC(위 설명)
  record...        녹화 설정(위 "녹화 저장")

영상
Windows Graphics Capture로 선택한 창 또는 모니터만 캡처합니다.
프로그램 창은 제목 표시줄과 테두리를 빼고 실제 내용(클라이언트 영역)만 송출합니다. 창의 보이는 프레임과 클라이언트 영역을 실제 좌표(물리 픽셀)로
매 프레임 비교해 잘라내므로 창 크기·최대화·다른 모니터·배율이 바뀌어도 따라갑니다. Windows가 확대해 그리는 오래된(DPI 비인식) 프로그램은 경계의
섞인 1픽셀도 뺍니다. Edge/Chrome 앱 창처럼 프로그램이 내용 영역 안에 제목 표시줄을 직접 그리는 경우에는, 프로그램이 제목 표시줄·창 버튼이라고
응답하는(WM_NCHITTEST) 줄이 창 폭 전체에 걸쳐 있을 때만 그 줄까지 뺍니다. 탭·메뉴·도구 모음처럼 내용으로 응답하는 부분은 자르지 않습니다.
이 판별은 배율 인식(Per-Monitor DPI) 프로그램에만 적용하며, 응답하지 않거나 판별할 수 없는 프로그램은 내용 영역 전체를 송출합니다.
전체 화면(모니터)은 선택한 모니터를 그대로 송출하며 자르지 않습니다.
H.264(High, B-프레임 없음, BT.709, 1초마다 키프레임)로 인코딩합니다. GPU 인코더(NVIDIA NVENC, Intel Quick Sync, AMD AMF)를
시작할 때 실제로 시험해 보고 쓸 수 있는 것을 고릅니다. 시작에 실패하면 다음 인코더로 다시 시도하고, 없으면 CPU 인코더(libx264)를 쓰며 이벤트 기록에 알립니다.
프레임은 송출 목표값입니다. 창이 바뀌지 않거나 원본 모니터 주사율이 낮으면 새 화면은 그만큼만 생기고 나머지는 직전 화면을 반복합니다.
이 경우 이벤트 기록에 원본 주사율을 알리고, 성능 기록에 캡처/송출/새 화면/인코딩 프레임을 따로 표시합니다.
인코딩이 설정 프레임을 따라가지 못하면 이벤트 기록에 경고를 남기고, 지연이 쌓이지 않도록 늦은 프레임을 건너뜁니다(같은 길이의 음성도 함께 건너뛰어 동기화를 유지).
재생 화질 메뉴의 낮은 화질은 시청자가 고를 때 MediaMTX가 FFmpeg로 실제로 다시 인코딩한 스트림입니다. 아무도 보지 않으면 10초 뒤 종료합니다.

오디오
시스템 소리는 WASAPI 루프백으로 캡처합니다. Windows 10 빌드 20348 이상에서는 FRAME Console 자신의 소리(이 PC의 수신 화면 소리)는 제외합니다.
그보다 오래된 Windows에서는 출력 장치 전체 소리를 캡처하므로 송출 PC에서 수신 화면 소리를 켜면 소리가 반복될 수 있습니다.
마이크는 Windows 기본 녹음 장치를 사용합니다. 설정 > 개인 정보 및 보안 > 마이크에서 데스크톱 앱 접근이 꺼져 있으면 오류를 표시합니다.
두 소스는 48 kHz 스테레오로 변환해 섞고 Opus로 인코딩합니다. 송출 중에도 음량과 음소거를 바꿀 수 있습니다.
수신 화면의 음량과 음소거는 그 시청자의 재생에만 적용됩니다.

제한 사항
최소화한 창은 Windows가 화면을 갱신하지 않아 마지막 화면이 계속 송출됩니다(이벤트 기록에 표시). 창을 선택하자마자 최소화된 상태로
송출하면 원본 크기를 알 수 없습니다(이벤트 기록에 "원본 크기 미확인" 표시). 창이 다시 그려지면 출력 화면 안에 배치됩니다.
자체 제목 표시줄을 그리면서 그 영역을 일반 내용으로 응답하는 프로그램은 제목 표시줄이 남을 수 있습니다(제목 표시줄 판별 불가).
Chrome, Edge 같은 Chromium 기반 창은 다른 창에 완전히 가려지면 스스로 그리기를 멈춰 화면이 멈추거나 검게 보일 수 있습니다.
보호된 콘텐츠(DRM 영상 등)는 검게 캡처됩니다. 원격 데스크톱 연결을 끊거나 화면을 잠그면 캡처가 멈출 수 있습니다.
Windows 10에서는 캡처 중인 창에 노란 테두리가 표시될 수 있습니다(Windows 11은 표시하지 않음).
되감기 시점의 정확도: 녹화 파일 경계마다 시각 매핑 오차가 약 0.1초 이내로 측정되었습니다(장시간에서는 시계 차이로 달라질 수 있음).
녹화 시점과 채팅 기록의 동기화(지난 구간의 채팅 다시 보기)는 지원하지 않습니다.

로그
data\logs\frame-console-*.log  실행 기록(FFmpeg, MediaMTX 출력 포함)
data\logs\stats-*.csv          송출 중 1초마다 측정값(캡처/송출/새 화면/인코딩 fps, 건너뛴 프레임, 서버 수신 비트레이트, 시청자 수, 음량, 녹화 크기)
data\runtime\mediamtx.yml      송출할 때 만든 MediaMTX 설정
프로그램 폴더에 쓸 수 없으면 %LOCALAPPDATA%\FrameConsole을 사용합니다.
