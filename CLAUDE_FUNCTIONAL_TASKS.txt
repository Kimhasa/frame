역할과 UI 기준
Claude는 실제 기능 연결, C++ 백엔드, 서버, 성능 최적화와 배포를 맡아. 현재 HTML/CSS를 재사용하고 UI를 다시 만들지 마. 프레임워크로 이관하거나 새 대시보드, 큰 화면 제목, 설명 카드, 데모 표시를 추가하지 마.
‘화면 송출’, ‘스트림 수신’ 같은 큰 제목과 시작·연결 버튼 옆 대기·준비됨·송출 중 배지를 다시 추가하지 마. 오류와 필요한 조치는 기존 오류·알림 영역을 사용해.
썸네일·프로필·제목·부제목을 묶은 카드, 구분선 제거, 설정 톱니바퀴와 새로고침·연결 아이콘을 유지해. Pretendard와 기존 입력·선택·음량·포커스 스타일도 유지해.
사이드바는 기본 폭 220px를 유지하고 확대 보기를 눌렀을 때만 72px 아이콘 메뉴가 돼. 상세에 들어갔다고 자동으로 축소하지 마. ‘스트리밍’ 문구는 제거했고 메뉴 이름은 ‘송출 하기’, ‘전체 수신 목록’이야. 상세에서는 전체 수신 목록 메뉴가 활성화되지 않으며 클릭하면 현재 수신을 정리하고 목록으로 돌아가.
영상 상세 상단의 목록으로·송출명·시간·연결 설정·수신 종료는 제거했어. 다시 추가하지 마. 영상 정보는 상단 버튼의 모달에서 보고, 수동 연결은 전체 수신 목록에서 제공해. 영상 정보 사이드바나 큰 좌우 여백을 되살리지 말고 원본 영상 비율을 유지해.
채팅은 상세 진입 시 기본으로 열리고 사용자가 닫거나 다시 열 수 있어. 글자 수 표시는 제거했으니 다시 추가하지 마. 메시지 입력 제한 자체는 유지해.
reference/와 UI_LOCK.json은 0.4 원본으로 보존하고, 현재 UI 기준은 reference-v05/와 UI_V05_LOCK.json을 사용해. node tools/verify-ui-v05.mjs로 확인해. 기준 해시를 임의로 갱신해서 디자인 변경을 숨기지 마.

내부망 영상 목록과 자동 연결
수신자는 공통 내부 주소에 접속하고 목록의 영상을 클릭하면 시청할 수 있게 해줘. 매번 IP와 스트림 ID를 입력하지 않아도 돼야 해.
여러 송출 PC를 한 목록에 모으는 등록·조회 구조를 구현해. 중앙 목록 서버와 영상 중계 서버를 같은 PC에 둘 수 있지만, 현재 각 PC가 자신의 MediaMTX를 실행하는 구조도 검토해서 실제 연결 경로를 명확하게 해줘.
송출 시작 시 자동 등록하고 종료 시 제거해. 비정상 종료나 네트워크 단절도 응답 만료 등으로 처리해서 종료된 방송이 계속 라이브로 남지 않게 해줘. UI와 목록의 상태는 실제 서버 상태를 기준으로 해.
UI_HANDOFF.txt의 GET /api/broadcasts 계약을 구현하고, 목록 갱신과 검색·클릭 흐름을 연결해. 송출명과 PC 이름은 실제 데이터로 제공하고 원본 방송과 파생 화질 스트림을 중복 표시하지 마.
썸네일은 실제 캡처 또는 스트림에서 주기적으로 만들고 캐시해. 카드마다 별도 고해상도 WebRTC 영상을 계속 디코딩하지 마. 썸네일 생성 부하와 갱신 간격을 검증해.
시청자에게 필요한 읽기 전용 목록·재생 API를 제공하고, MediaMTX 관리 API나 송출 PC 네이티브 제어 명령은 노출하지 마. 목록과 재생 권한을 일치시켜.
폐쇄망에서 외부 서비스, CDN, 외부 STUN/TURN을 필수로 요구하지 마. 내부 DNS나 고정 주소 등 접속 방법을 문서화하고 서로 다른 망 구간에서는 실제 경로와 포트를 검증해.

송출자·수신자 수동 연결 유지
기본 목록 사용과 별도로 일반 사용자도 수동 연결을 사용할 수 있어야 해. 관리자 전용으로 숨기거나 기능을 제거하지 마.
송출자는 연결 설정에서 서버 IP/호스트, 스트림 ID, 송출 포트와 시청 포트를 직접 설정할 수 있어야 해. 수신자는 수동 연결 창에서 IP/호스트, 시청 포트와 스트림 ID를 지정해.
입력값을 실제 연결에 적용하고 성공·실패를 실제 이벤트로 판단해. 마지막 입력 보관 시 실패한 임시 편집과 적용한 설정을 구분해. 자동 연결이 수동 설정을 조용히 덮어쓰지 않게 해.
기존 C++에서 serverHost가 내장 서버의 광고 주소인지 외부 MediaMTX 주소인지 먼저 확인해. 설정 의미를 혼동하지 말고 외부 서버를 지원할 경우 내장/외부 서버의 프로세스 관리와 실제 publish/read 경로를 구분해 구현·문서화해. 입력창만 있고 다른 IP가 거부되는 상태를 외부 서버 연결 완료로 보고하지 마.
잘못된 IP, 포트 점유, 도달 불가, 방송 종료와 연결 취소를 처리하고 목록 서버를 쓰지 못해도 유효한 개별 수신 주소로 연결할 수 있게 해.

프로그램 창·전체 화면·모니터 선택
기존 프로그램 창 선택 기능을 보존하고 새 전체 화면 탭에 실제 모니터 목록을 연결해. UI_HANDOFF.txt의 frame:request-monitors / setMonitors / frame:select-monitor 계약을 사용해.
프로그램 창은 실제 제목·아이콘·썸네일을 제공하고 같은 제목도 구분해. 모니터는 안정적인 ID, 번호, 해상도, DPI 배율, 주 모니터와 실제 썸네일을 제공해.
선택한 모니터 한 대 전체를 실제로 캡처해. 여러 모니터의 서로 다른 해상도·배율·배치와 연결 해제를 처리해. 실패하면 다른 창이나 전체 바탕화면으로 임의 전환하지 마.
선택만으로 송출하거나 녹음을 시작하지 마. 기존 시작 버튼을 사용하고, 송출 중 대상 변경은 실제로 안전할 때 지원해. 불가능하면 기존 방식으로 중지 후 변경하도록 알려줘.

화질과 FPS·비트레이트
현재 캡처 → 크기 변환 → 인코딩 → 네트워크 → 브라우저 디코딩을 점검하고 불필요한 복사, 중복 변환과 과도한 압축을 줄여줘. 원본 비율을 유지하고 작은 글자와 빠른 움직임을 각각 검증해.
기존 화질과 FPS 선택 범위, 기본값과 수동 입력을 유지해. UI 숫자나 확대만으로 화질·FPS가 향상됐다고 보고하지 마. 144/165fps는 목표값과 실제 측정값을 구분하고 조용히 낮추지 마.
자동 비트레이트는 최종 송출 가로·세로 크기, FPS, 코덱과 인코더를 고려해 목표값을 계산하고 실제 인코더에 적용해. 현재 UI의 단순 선형 계산은 초기 프리셋이므로 적절한 근거와 실제 결과를 확인해.
UI 목표값과 인코더 설정값을 일치시키고 실제 측정 비트레이트는 구분해. 수동값을 자동으로 덮어쓰지 마. 실시간 망 혼잡 적응 기능은 별도 기능으로 구분해.
GPU 지원 여부와 인코더 제한을 확인하고 소프트웨어 대체 경로의 실제 한계도 보고해. 큐가 무한히 쌓이지 않도록 지연과 드롭 프레임을 측정·관리해. 기존 WebRTC 호환 H.264 설정과 오디오 동기화도 유지해.

방송 전체 DVR와 실시간 복귀
현재 방송의 시작부터 최신 시점까지 되감을 수 있게 구현해. 최근 10분 등 고정 길이로 제한하지 마. 3시간째 송출 중에도 시작 후 10분 지점으로 이동할 수 있어야 해.
송출 시작 시 서버 측 녹화를 함께 시작하고 방송 중에는 시작 부분을 포함한 전체 영상을 유지해. 늦게 접속한 수신자도 보관된 처음 부분을 볼 수 있어야 해. 새 방송은 고유 ID로 이전 방송과 구분해.
MediaMTX 녹화·재생과 시간 인덱스를 연결하고 적절한 분할 구간을 사용해. 방송 종료를 기다려야 과거 영상이 열리는 구조로 만들지 마. 실제 재생 가능한 최신 시점과 녹화 지연을 반영해.
탐색 요청마다 전체 파일을 다운로드하거나 긴 방송 전체를 브라우저 메모리에 올리지 마. 필요한 구간만 제공하고 시간축·키프레임·구간 경계·송출 설정 변경·빈 구간을 처리해.
UI_HANDOFF.txt의 frame:seek / frame:live / setTimeline 계약을 연결해. 현재 UI는 요청 이벤트와 표시만 준비되어 있어. WebRTC 영상의 currentTime 숫자만 바꾸거나 가짜 재생 시간을 넣어 DVR 완료로 처리하지 마.
과거 시점 선택 시 실제 그 시점부터 재생해. 일시정지·이어 보기·음량·음소거·화질·확대·전체 화면을 실제 미디어에 적용하고 타이핑 중 키보드 입력을 가로채지 마.
영상 영역 클릭으로 일시정지·이어 보기를 전환하는 UI도 유지해. 음량·화질 메뉴·재생바·채팅 입력 클릭이 재생을 멈추거나 Space/K 단축키에 가로채이지 않게 해.
실시간 버튼은 과거 재생을 종료하고 현재 재생 가능한 최신 라이브로 복귀시켜. 실제 전환 성공 후 상태를 갱신하고 기본 전송 지연이 0이 된 것처럼 표시하지 마. 영상·음성 중복 재생과 동기화 오류를 방지해.
시청자별 재생 위치를 독립적으로 관리해서 한 사람의 되감기가 송출이나 다른 수신자에게 영향을 주지 않게 해.

저장 용량과 부하 최적화
이미 인코딩한 송출 영상을 재사용해서 추가 재인코딩 없이 녹화하는 경로를 우선 검토해. 동일 영상을 불필요하게 여러 번 인코딩하거나 중복 보관하지 마.
재인코딩 없는 저장의 부하 절감과 비트레이트 조정의 용량 절감을 구분해. 파일 분할이나 ZIP 압축만으로 영상 용량이 크게 줄어든다고 보고하지 마.
실제 화질을 확인하며 가변 비트레이트와 인코더 설정을 검토해. 정적 글자 화면과 움직임 많은 화면을 따로 측정하고 수동 설정·해상도·FPS를 몰래 바꾸지 마. 과거 구간만 임의로 저화질·저프레임으로 바꾸지 마.
코덱 변경 시 대상 브라우저·WebView2·MediaMTX·GPU의 실제 호환성을 검증해. 단순히 압축률이 좋다는 이유로 교체하지 마.
디스크에 분할 기록하고 메모리 사용을 제한해. 저장 위치·용량 상한·종료 후 보관 정책을 설정 파일로 관리해. 현재 방송의 시작 부분을 몰래 삭제해 전체 되감기를 깨뜨리지 마.
디스크 부족·녹화 실패를 명확히 알리고 가능한 경우 라이브 송출을 유지해. 실제 남은 탐색 범위를 반영해. 실제 파일 크기와 평균 비트레이트, CPU·GPU·메모리와 화질을 비교해 최적화 효과를 보고해.

송출자 채팅과 송출 설정 모달
송출자도 송출 화면에서 본인 방송의 채팅을 바로 보고 전송할 수 있어야 해. 수신 화면으로 이동하거나 자기 영상을 다시 재생해야 채팅이 보이는 구조로 만들지 마.
UI에는 오른쪽 송출자 채팅과 ‘송출 시작’ 바로 왼쪽의 ‘송출 설정’ 버튼을 추가했어. 기존 영상 및 오디오, 시청 주소는 이 버튼으로 여는 하나의 모달에 모았어. 현재 배치를 유지하고 설정 카드를 오른쪽에 다시 늘어놓지 마. 송출 연결 설정은 기존 별도 모달로 유지해.
송출 시작·방송 등록 시 실제 본인 방송의 ID로 채팅방에 연결하고 실제 연결 완료 뒤에만 전송을 활성화해. 송출 시작 전·실패·종료·재시작과 서버 연결 끊김을 실제 상태로 처리해. running=true만 보고 채팅 연결 성공으로 표시하지 마.
UI_HANDOFF.txt의 setSenderChatState / setSenderMessages / appendSenderMessage / ackSenderMessage 계약을 사용해. 일반 API의 두 번째 context 인수로 sender를 지정해도 돼. 전송·이름 변경 이벤트의 context와 broadcastId를 실제 방에 맞게 처리해.
송출자가 다른 방송을 시청하더라도 송출자 채팅은 계속 본인 방송의 방을 유지해야 해. 시청 방송 채팅과 메시지·초안·전송 확인이 섞이지 않게 해. 수신 연결을 종료하거나 전체 목록으로 돌아갔다고 송출자 채팅방이나 다른 사용자의 연결까지 종료하지 마.
다른 PC의 수신자가 쓴 메시지가 송출자에게 도착하고, 송출자가 답한 메시지가 같은 방의 수신자들에게 도착하는지 검증해. 별도 방송의 채팅방과 격리하고 재연결 때 중복 메시지나 이전 방송의 메시지가 섞이지 않게 해.
설정 모달 안에서도 화질·프레임·오디오·음량·고급 설정·주소 복사·시청 이동을 실제 기능에 연결해. 모달에서 Enter를 눌렀다고 송출을 시작하지 마. 송출 중 설정 잠금과 음량 조절은 기존 동작을 보존하고 서버 오류가 닫힌 모달 뒤에만 숨어 있지 않게 처리해.

실시간 채팅
현재 오른쪽 채팅 패널은 UI와 이벤트만 구현돼 있어. UI_HANDOFF.txt의 setChatState / setMessages / appendMessage / frame:send-message / ackMessage 계약에 실제 서버 송수신을 연결해.
방송별로 독립된 채팅방을 만들고 실제 방송 ID를 사용해. 다른 방송의 메시지가 섞이지 않도록 입장·퇴장과 구독 해제를 처리해. 송출자와 수신자가 같은 방에서 대화할 수 있게 해.
표시 이름과 메시지 ID·방송 ID·서버 시각을 서버에서 관리하고, 인증을 쓰는 환경에서는 인증된 사용자 신원과 표시 이름을 연결해. 클라이언트가 보낸 이름이나 clientId를 사용자 인증으로 간주하지 마.
각 사용자가 이름 설정에서 자신의 표시 이름을 지정·변경할 수 있게 해. UI의 frame:set-chat-name 요청을 실제 방 세션에 연결하고, 이름 길이·공백·금지 값·중복 정책을 검증해. 한 사람의 이름 변경이 다른 사용자의 이름을 바꾸지 않게 하고 이후 메시지에 서버가 확정한 이름을 사용해. 서버가 거부하거나 정규화한 경우 설정 UI와 표시 이름도 일치시켜. 브라우저 저장 값은 편의 설정이며 인증을 대체하지 않아.
WebSocket 등 내부망에서 동작하는 실제 메시지 경로를 구현하고, 초기 기록·새 메시지·전송 확인·중복 제거·재연결을 처리해. 서버 확인 없이 성공 표시하거나 실패한 메시지를 조용히 지우지 마.
연결 끊김·권한 없음·전송 실패를 실제 상태로 반영하고 전송 중 새로 작성한 초안이 이전 메시지의 확인 응답 때문에 사라지지 않도록 해. Enter 전송과 Shift+Enter 줄바꿈, 한글 입력 조합을 검증해.
서버에서도 메시지 길이·전송 빈도·방 접근 권한을 검증해. HTML이나 스크립트를 실행하지 않도록 텍스트로 전달·표시해. 실제 필요한 범위의 기록만 내려주고 브라우저·서버 메모리가 무한히 쌓이지 않게 해.
채팅은 기본적으로 현재 방송의 실시간 대화야. DVR 재생 위치와 과거 채팅 기록을 동기화하는 기능은 별도 요청 전까지 구현 범위에 넣지 마.
목록·영상·DVR와 함께 외부 서비스 없이 내부망에서 동작해야 해. 영상 연결과 채팅 연결은 구분해서 처리하고 채팅 서버 장애가 영상 송출을 중단시키지 않게 해.

PiP·오디오·프로세스
PiP 버튼은 실제 video와 브라우저 지원에 따라 활성화하는 UI 코드가 있어. 대상 브라우저와 WebView2에서 실행 여부를 검증하고 연결 해제·화질 전환·라이브/DVR 전환 때 이전 PiP 창과 오디오가 남지 않게 처리해.
기존 시스템 오디오·마이크·믹싱·음소거·볼륨과 영상 동기화를 유지해. 수신자의 재생 음량이 전체 송출 믹스를 바꾸지 않게 해.
프로그램이 시작한 자식 프로세스만 종료하고 다른 FFmpeg나 MediaMTX를 이름으로 일괄 종료하지 마. 기존 Job Object 관리와 포트·오디오·인코더 실패 처리를 보존해.

다른 IP를 가진 실제 PC의 접속 검증
송출 PC(A)에서 실행 프로그램을 켜고, 별도 PC(B)가 A의 실제 내부망 IP와 시청 포트로 접속해 영상을 보는 과정을 실제로 검증해. 한 PC에서 두 브라우저를 여는 테스트와 구분해. 같은 물리 PC의 VM을 사용하면 별도 OS·네트워크 주소의 VM 검증이라고 명시하고 물리적으로 다른 PC의 검증과 구분해.
먼저 현재 소스·설정·빌드 결과를 확인하고 새 UI가 포함된 실제 FrameConsole.exe를 준비해. localhost:5317의 UI 검토 서버나 review=1 예시 데이터로 실제 LAN 송출 검증을 대신하지 마.
PC A의 유효한 LAN IP와 네트워크 인터페이스를 확인해. 여러 NIC·VPN·가상 어댑터가 있으면 PC B에서 도달 가능한 주소를 선택해. 수신자에게 localhost, 127.0.0.1, 0.0.0.0을 접속 주소로 안내하지 마.
시청용 HTTP 서버는 해당 LAN 인터페이스 또는 전체 인터페이스에서 수신하도록 하고 실제 바인딩과 포트 점유를 확인해. 현재 소스의 HttpServer는 INADDR_ANY를 사용하지만 실행 환경에서 실제 접속까지 확인해야 해.
MediaMTX의 브라우저 신호 처리와 실제 영상 전송을 구분해. 현재 구조는 시청 HTTP 서버가 로컬 MediaMTX WHEP에 전달하고 WebRTC 미디어 포트는 LAN에서 도달해야 해. 내부 전용 MediaMTX 관리·신호 포트를 무작정 외부에 공개하지 마.
현재 설정 예시의 viewerPort는 8889, iceUdpPort/iceTcpPort는 8189지만 실제 설정 파일과 실행 상태를 기준으로 안내해. WebRTC가 PC B에서 도달 가능한 주소를 ICE 후보로 제공하는지도 확인해. 웹페이지만 열리고 영상은 안 나오는 경우까지 진단해.
필요한 HTTP·WebRTC·채팅 포트, 프로토콜과 허용 대상을 문서화해. 방화벽 전체 해제에 의존하지 말고 필요한 프로그램·포트만 환경 정책에 맞게 허용해. 서로 다른 VLAN·서브넷이면 실제 라우팅과 접근 허용 여부를 확인해. 인터넷이나 외부 중계 서버를 기본 전제로 두지 마.
PC B는 개발 도구나 FFmpeg 설치 없이 브라우저로 접속해야 해. 실제 접속 주소를 복사 가능한 형태로 제공해. 목록 주소는 http://<PC-A-LAN-IP>:<viewerPort>/, 직접 수신 주소는 http://<PC-A-LAN-IP>:<viewerPort>/<streamPath> 형태를 현재 배포 구성에 맞게 검증해서 안내해.
PC A에서 먼저 1080p/60fps 등 확인 가능한 설정으로 움직이는 창과 선택한 오디오를 송출해. PC B에서 목록 조회·카드 선택·수동 연결·영상 변화·소리를 확인해. 웹 UI가 열리거나 서버 로그에 요청이 찍힌 것만으로 수신 성공으로 처리하지 마.
이후 PC B의 일시정지·이어 보기·화질 전환·전체 화면·방송 처음으로 되감기·실시간 복귀·이름 설정·실제 양방향 채팅을 검증해. 가능하면 다른 수신 PC(C)를 추가해서 독립 재생 위치와 채팅방 동작도 확인해. 높은 FPS 성능은 기본 LAN 수신 성공과 별도로 측정해.
송출 중지·프로그램 종료·네트워크 단절·서버 재시작 후 PC B의 오류와 재연결도 확인해. 수신자를 종료해도 송출이나 다른 시청자가 끊기지 않아야 해.
보고서에는 PC A/B의 구분, IP·포트·OS·브라우저, 실제 URL, 설정, 검증 항목별 결과와 실패 원인을 적어. 가능한 경우 서버에서 확인한 실제 원격 접속 주소, 브라우저의 ICE 연결 상태·선택 경로·수신 프레임·비트레이트와 화면을 증거로 남겨.
다른 PC를 제어할 도구나 실제 장비가 없으면 ‘별도 PC 접속 미검증’이라고 명시해. 그 경우에도 A의 실행 파일·주소·필요 포트·진단 로그와 B에서 따라 할 접속·확인 절차를 완성해줘. 필요한 B측 조작을 사용자에게 짧게 안내하고, 실제 결과를 받기 전에는 성공으로 보고하지 마. 필요한 구현·빌드 작업은 계속 진행해.

검증과 납품
먼저 node work/build-console.mjs, node tools/verify-ui-v05.mjs를 실행해. 기존 네이티브 빌드 구성과 검증 도구를 확인하고 변경한 기능에 맞게 검증해.
동일한 client area에서 현재 UI와 비교해. 목록·검색·수동 연결·모니터 선택·송출·수신·과거 탐색·실시간 복귀·오류·좁은 화면을 확인하고 큰 제목이나 상태 배지를 되살리지 마.
여러 송출 PC와 수신자, 다른 IP의 실제 내부망 수신을 가능한 장비에서 검증해. 한 PC의 루프백 테스트를 다른 PC 접속 검증으로 보고하지 마.
채팅은 두 개 이상의 실제 클라이언트에서 방 분리·송수신·재연결·중복 전송·한글 입력을 확인해. 한 화면의 예시 메시지나 로컬 반향을 실제 채팅 서버 검증으로 보고하지 마.
처음 구간 탐색, 녹화 경계, 설정 변경, 늦은 접속, 시청자별 다른 재생 위치, 서버 단절, 디스크 부족과 재시작을 확인해. 짧은 테스트와 실제 3시간 장시간 검증을 구분해.
인터넷과 개발 도구가 없는 실행 환경을 확인하고 폰트·라이선스·런타임·FFmpeg·MediaMTX·실제 필요한 DLL을 포함해 배포해. UI 작업 폴더 바깥의 review=1 시각 검토 데이터는 제품에 복사하지 마.
최종 실행 진입점은 dist/FrameConsole/FrameConsole.exe야. 새 UI가 실제 배포 폴더와 exe 실행 화면에 반영되도록 패키징하고 버전·의존성·설정·검증 결과를 정리해.
계획 설명에서 끝내지 말고 실제 구현·빌드·실행 검증까지 진행해. 완료한 기능과 실제 검증 환경, 미완료·미검증 항목을 명확히 구분해. 기존 Git 규칙과 무관한 변경 보존 원칙도 유지해.
