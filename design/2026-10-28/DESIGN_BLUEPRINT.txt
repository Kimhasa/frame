FRAME 화면 구조와 사용자 흐름 v1.1
작성일: 2026-10-28

제품 방향
기술자가 서버 주소를 입력하는 수신 도구에서, 방송을 찾아 바로 시청하고 직접 방송할 수 있는 서비스로 탐색 구조를 확장한다. 기존 캡처·플레이어·화질 기능을 그대로 재사용한다. 서버 IP·포트·스트림 ID의 직접 제어는 연결 설정과 직접 연결에 남긴다.

공통 화면 구조
상단: FRAME, 방송·채널 검색, 알림, 프로필.
기본 메뉴: 라이브, 팔로잉, 다시보기, 클립, 시청 기록. 방송하기와 채널 관리로 이동할 수 있다.
관리 화면: 방송하기, 채널 관리, 채팅 관리, 방송 통계, 수익·정산, 미션, 투표, 포인트, 멤버십, 외부 도구 연결.
계정 화면: 내 프로필, 계정 및 보안, 설정, 결제 내역.
서비스 관리자 화면: 서비스 상태, 신고 관리, 활동 기록. 일반 시청자 메뉴와 구분한다.
시안의 검토 도구와 운영 메뉴가 실제 권한 관리를 구현한 것으로 해석되지 않도록 한다.

시청 흐름
라이브 목록 → 방송 카드 선택 → 기존 플레이어와 기본 열린 채팅.
방송 정보 → 채널 → 팔로우·멤버십·후원.
공유 → 방송 링크 복사. 서버의 내부 송출 주소와 구분한다.
채팅 하단 → 후원 또는 참여 메뉴 → 미션·투표·포인트·클립.
검색 → 결과 없음 또는 방송·채널 결과 → 시청/채널.
팔로잉 → 로그인 필요 또는 팔로우한 채널 → 방송 시작 알림 → 시청.
방송 종료 → 종료 상태 → 채널 또는 공개 다시보기. 로컬 녹화 파일을 자동으로 공개 다시보기로 취급하지 않는다.

방송 흐름
방송하기 → 화면 선택 → 프로그램 창/전체 화면 → 대상 선택 → 기존 미리보기.
방송 설정은 기존 영상·오디오·프레임률·비트레이트·녹화 UI를 재사용한다.
필요한 경우 연결 설정 → 서버 주소·포트·스트림 ID를 직접 지정한다.
방송 정보 수정 → 제목·카테고리·태그·공개 범위.
방송 시작 → 본인 방송 채팅 확인 → 방송 종료 확인 → 종료 요약 → 녹화 관리.
화면 선택과 설정 저장만으로 방송을 시작하지 않는다. 이미 방송 중인 상태의 대상 변경 정책은 기존 구현을 따른다.

계정·후원·참여 흐름
로그인 → 제공자 연동 또는 이메일 → 프로필 → 계정 및 보안. 제공자는 운영 결정 전까지 후보 시안이다.
무료 관심 등록은 팔로우, 유료 정기 가입은 멤버십, 일회성 금액·메시지는 후원으로 구분한다.
후원은 금액/메시지/수단/동의/처리/결과 상태를 구분한다. 실제 PG·검증·정산·환불 구현을 대신하지 않는다.
무료 미션과 미션 후원은 금액·결제 유무로 구분한다. 성공 판정·기한·취소 기준은 실제 운영 설계가 필요하다.
투표, 질문, 포인트 보상, 시청 보상, 다른 방송으로 연결은 채팅 참여 영역에서 진입한다. 영상 제어 바에 새 참여 기능을 끼워 넣지 않는다.

디자인 원칙
현재 밝은 FRAME 테마와 어두운 상단 헤더, 녹색 강조, Pretendard를 유지한다.
기본 텍스트는 충분히 진하게 하고, 부가 정보만 보조 색상을 사용한다. 반복 상태·설명 카드·데모 표시·과도한 대제목을 추가하지 않는다.
기존 화질 메뉴·음량·재생바·재생 버튼·PIP 등의 모양과 기능을 유지한다. 화면 구조를 바꾸기 위해 캡처·인코딩·미디어 요소 수명을 변경하지 않는다.
좌측 메뉴는 시청 상세 진입만으로 줄이지 않는다. 기존 확대 보기 동작을 눌렀을 때만 축소한다.
시청 상세에서는 라이브 메뉴의 선택 상태를 해제하여 라이브 목록으로 다시 이동할 수 있게 한다.
방송 정보는 상단 버튼의 모달에 둔다. 좌측 정보 패널, 목록 이동·제목·시간의 반복 상단 줄, 연결 설정·수신 종료 버튼을 시청 화면에 다시 추가하지 않는다.
방송 시작 버튼 옆의 대기·준비됨·송출 중 배지는 사용하지 않는다.
카드는 하나의 선택 영역으로 구성한다. 아이콘·제목·채널명을 함께 읽을 수 있게 하고, 긴 제목은 말줄임과 전체 제목 접근성을 제공한다.
공유할 화면 선택창은 기존 요청에 따라 넓은 모달과 2열 썸네일, 앱 아이콘·창 제목 행으로 설계한다. 전체 원본을 보존하고 세로·울트라와이드에 필요한 여백을 허용한다.
모바일은 탐색 영역을 압축하고 채팅·주변 정보의 배치를 조정하되 기존 플레이어 컴포넌트의 동작을 재설계하지 않는다.

상태 설계
각 화면의 정상 상태 외에 불러오는 중, 내용 없음, 실패, 재시도, 완료, 권한 없음, 방송 종료 등 필요한 상태를 SCREEN_INVENTORY.txt에 명시한다.
클라이언트의 미리보기 실패와 실제 캡처 불가, 수동 화질과 자동 화질, 라이브 과거 구간과 공개 다시보기를 서로 다른 상태로 취급한다.
실제 적용 상태를 얻기 전에는 숫자·성공·활성화 상태를 운영 UI에 고정 값으로 넣지 않는다. 시안 데이터는 검토용 파일 안에만 둔다.

시안 검토 순서
1차: 라이브 목록 → 시청 → 방송하기 → 공유할 화면 → 연결/정보/닉네임, 데스크톱·모바일과 오류 상태.
2차: 계정, 채널, 팔로잉, 알림, 채팅 관리, 녹화와 다시보기.
3차: 후원, 멤버십, 미션, 투표, 포인트, 수익·정산, 외부 연동과 운영.
기능 개발의 P0/P1/P2/P3는 기존 기능 목록을 유지한다. 시안에서 먼저 그린 후원 화면이 이번 구현 우선순위를 자동으로 올리지는 않는다.
