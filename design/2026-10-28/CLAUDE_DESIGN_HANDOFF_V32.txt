v3.1 인계 기준은 유지하고 내 설정만 이번 v3.2를 우선한다.
실제 앱 전체 반영·OAuth·결제·송출 기능 개발을 이 문서만으로 승인됐다고 해석하지 마.

1. 화면과 동작
프로필, 계정 연결, 보안 및 기기, 알림, 재생은 배경 없는 상단 밑줄 탭이다.
프로필은 사진·닉네임·자기소개·사용자 ID를 같은 폭으로 정렬하고 저장/취소를 제공한다.
알림·재생의 토글은 별도 저장 버튼 없이 즉시 반영하는 UI다.
필드 제약과 오류 문구는 유지하되 의미 없는 설명과 반복 표시는 줄인다.
본문과 보조 설명은 읽을 수 있는 대비를 유지하고, 주요 터치 영역은 44px로 제공한다.

개인 profile.handle은 사용자 ID로 표시한다. 공개 채널의 주소는 channel.handle이다.
현 상태는 두 값이 분리되어 있으므로 사용자 ID 변경을 채널 주소 변경 완료로 표시하지 마.
사용자 ID 검증은 영문/숫자로 시작하는 3~24자, 이후 영문/숫자/_/-를 허용한다.

2. 로컬 상태 보존
원래 F.accountDesign, form id, input name/data-v3-scope, v3-account action을 재사용한다.
프로필 초안은 다른 설정을 보고 돌아와도 유지하고, 취소는 마지막 저장값으로 복원한다.
오류를 수정하면 남은 빨간 표시와 aria-invalid를 함께 정리한다.
저장·취소 후 포커스를 안정적인 위치로 돌리고, 토글의 key와 키보드 포커스를 보존한다.
좁은 화면에서는 선택 탭이 가로 영역 안에 보이게 한다.

3. URL과 상태
profile → section=profile
security → section=account 또는 section=security
preferences → section=notifications 또는 section=playback
섹션별 직접 진입과 뒤로가기/앞으로가기에 같은 메뉴가 표시되어야 한다.
알림 차단 상태는 알림 탭, 재인증 필요 상태는 보안 및 기기 탭에 표시한다.
안내 모달을 읽고 닫는 것만으로 차단·재인증 상태가 해제된 것처럼 보이지 않게 한다.
다른 기기가 없으면 일괄 로그아웃 버튼은 비활성화한다.

4. 실제 기능과의 경계
네이버 연결은 기존 로컬 로그인 확인 후 복귀하는 흐름이며, 제공자 연결 상태를 저장하지 않는다.
이메일 변경은 입력 확인 모달까지만 제공하며 주소를 변경하거나 인증 메일을 보내지 않는다.
기기 목록의 제거는 시안 메모리에서만 처리한다. 실제 세션 폐기는 구현하지 않았다.
알림 차단 안내는 요청된 시안 상태이며 Notification.requestPermission 등 실제 권한 요청을 하지 않는다.
이 항목들을 실제 서비스에 연결할 때는 서버의 결과와 권한 상태를 기준으로 성공/실패를 표시해야 한다.

5. 파일과 보호 범위
v31-layout → v32-settings → v32-runtime → design-events 순서로 로드한다.
내 설정 스타일은 .v32-settings에 한정한다. 채널 관리·로그인·방송·기존 화질 UI를 재디자인하지 마.
preserved-player.js/.css/-data.js와 PLAYER_PRESERVATION.json의 8개 원본 참고 파일을 보존한다.
해시 기준을 덮어써서 변경 없음을 만들거나 실제 앱의 후속 작업을 되돌리지 마.
초기 v3.2 검증은 verification/v32/에 이전 기록으로 보존한다. 브라우저 크기 검토를 실물 모바일 기기나 실제 인증·보안 기능 검증으로 보고하지 마.

초기 자료 준비 명령은 node prepare-v32.mjs였다. 이전 캡처를 복사하므로 최신 자료 준비에는 사용하지 마.

제목을 반복하거나 화면 위치를 다시 설명하는 문구를 제거하고, 행·사진·저장 영역의 불필요한 경계선을 정리한다.
저장 상태 문구는 변경사항이 있을 때만 표시한다. 입력 조건·오류·보안·공개 범위 안내는 유지한다.
이후 수정과 개발 검수에는 DESIGN_DETAIL_STANDARD.txt를 적용한다. 선을 제거하면서 구분에 필요한 여백이나 조작 영역까지 축소하지 마.
최신 검증과 캡처는 verification/v32-detail/을 확인한다. verification/v32/는 초기 v3.2 검증으로 보존한다.
최신 자료 준비는 원래 프로젝트 폴더에서 node prepare-v32-detail.mjs를 사용한다. prepare-v32.mjs는 이전 캡처를 복사하므로 사용하지 마.
