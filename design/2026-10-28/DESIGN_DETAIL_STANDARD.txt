FRAME 디자인 상세 검수 기준
적용 범위: 화면 시안과 개발 인계 검수

1. 정보와 문구
사용자의 다음 행동, 선택의 차이, 실수 방지에 필요한 정보만 표시한다.
제목을 풀어 쓴 문장, 당연한 기능 설명, 화면 위치 설명은 제거한다.
입력 조건은 해당 입력칸에, 오류는 발생한 항목에 표시한다.
기술 정보는 필요한 관리 화면에서만 제공한다.
같은 기능은 같은 용어로 쓰고, 버튼은 실행할 행동을 짧게 표현한다.

2. 경계와 정렬
영역 구분은 간격과 제목을 우선 사용한다.
구분선은 서로 다른 작업 영역이나 반복 목록을 구분할 필요가 있을 때만 둔다.
카드 외곽선과 내부 구분선을 중복해서 사용하지 않는다.
입력칸 테두리, 활성 탭 표시, 오류와 경고의 구분은 유지한다.
본문 폭, 기준선, 행 간격, 버튼 높이와 아이콘 크기를 화면 사이에 통일한다.

3. 상태
기본, hover, focus, disabled, loading, empty, error, success 상태를 확인한다.
색상 외에도 문구·아이콘·형태로 상태를 구별할 수 있어야 한다.
로딩 중 중복 실행을 막고, 빈 화면과 실패 화면을 구별한다.
오류에는 가능한 다음 행동을 제공한다. 정상 입력으로 수정하면 오래된 오류를 지운다.
확인하지 않은 성공 상태나 실제로 적용되지 않은 값을 표시하지 않는다.

4. 조작과 화면 크기
키보드 탐색 순서, 보이는 포커스, Enter·Space·Escape 동작을 확인한다.
모바일에서 가로 넘침, 버튼 잘림, 메뉴 누락과 터치 영역을 확인한다.
긴 제목·이름·이메일·오류 문구, 빈 값과 여러 줄 입력으로 레이아웃을 확인한다.
줄임표를 사용해도 조작에 필요한 정보가 사라지지 않게 한다.

5. 변경과 이동
저장 후 적용과 즉시 적용을 구별한다. 변경이 없으면 불필요한 저장을 요구하지 않는다.
취소는 마지막 저장값으로 복원하고, 저장 실패 시 작성한 내용을 보존한다.
모달 닫기와 브라우저 뒤로가기는 예상한 이전 화면·탭·상태로 돌아가야 한다.
변경사항 유실이나 중요한 작업에만 확인 절차를 둔다.

6. 개발 인계
최종 시안, 허용한 변경 범위, 상태별 동작과 미확인 항목을 함께 기록한다.
시안의 예시 데이터·로컬 동작과 실제 인증·저장·통신 구현을 구분한다.
영상·플레이어·오디오·화질 제어는 동결한다. 별도 요청 없이 구조·스타일·동작을 수정하지 않는다.
검수는 실제 화면과 반응형 결과로 확인하며, 원본 비교 자료와 해시를 덮어쓰지 않는다.
