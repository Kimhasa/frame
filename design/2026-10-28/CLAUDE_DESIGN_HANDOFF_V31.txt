1. 적용 범위

README_V31.txt와 이 문서를 최신 UI 기준으로 읽고, 기존 CLAUDE_DESIGN_HANDOFF_V3.txt의 기능·원본 보존 경계를 함께 유지해. 현재 앱과 진행 중인 변경을 먼저 확인하고 사용자가 반영하기로 한 범위만 연결해.
v3.1은 독립 디자인 시안의 표현과 동선을 정리한 작업이다. 실제 앱, 인증, 결제, 송출 기능을 변경하거나 검증한 결과가 아니다. 시안을 운영 코드 전체에 덮어쓰거나 기존 P1~P3 기능 일괄 구현 지시로 해석하지 마.

2. 상태와 문구

빈 화면은 테두리 없는 간결한 구성으로 표시하고 제목·필요한 설명·다음 행동만 남긴다. 검색 결과 없음은 ‘검색어 수정’으로 검색 입력에 포커스를 돌려주고, 불러오기 실패는 ‘다시 시도’로 해당 화면을 다시 불러온다. 로딩에는 상태를 읽을 수 있는 접근성 이름과 aria 상태를 제공한다. 빈 데이터·로딩·오류를 모두 같은 안내나 버튼으로 처리하지 마.
일반 시청자의 방송 정보 모달에서 재생 화질·FPS·해상도·비트레이트·코덱·연결 방식·스트림 ID·고급 정보 표를 제거했다. 제목·채널·설명·카테고리를 선택 방송에 맞춰 표시하고, 설명이 없으면 해당 영역을 생략한다. 정보 자체가 없으면 짧은 안내와 닫기만 제공한다. 종료된 방송에 LIVE나 고정 시청자 수를 붙이지 마.
공유 모달도 선택 방송의 제목·채널·주소를 사용한다. 기본 공유에서 임베드 코드를 제거하고 같은 ‘방송 링크’ 문구의 시각적 반복을 줄였다. 시청·다시보기 등 공유를 열었던 화면으로 복귀하게 한다. 주소·제목을 첫 번째 예시 방송으로 고정하지 마.
방송자의 연결 설정과 ‘방송 상태’에 필요한 기술 정보는 유지한다. 시청 정보에서 숨긴 것을 이유로 방송자 조작이나 원본 화질 메뉴까지 제거하지 마.
중복 홍보·설명 문구를 축약했다. 정책 화면은 ‘이것은 시안’ 같은 개발자 설명 대신 정책 준비 중 상태를 제공한다. ‘가입자 없음’에서는 예시 가입자 수가 남은 상단 지표 행을 표시하지 않는다. 측정되지 않은 데이터를 0으로 채워 실제 결과처럼 보이게 하지 마.

3. 탭과 반응형

공개 채널, 검색 결과, 채널 관리의 가로 탭은 투명 배경과 활성 밑줄로 통일한다. 탭을 다시 렌더링해도 키보드 포커스를 보존하고, 좁은 화면에서는 탭 레일 안의 가로 스크롤을 허용한다. 카테고리 칩과 내 설정의 세로 메뉴는 각각의 기존 역할·스타일을 유지한다. 모든 선택 버튼을 일괄 밑줄 탭으로 바꾸지 마.
320px부터 넓은 데스크톱까지 콘텐츠를 볼 수 있어야 한다. 실제 브라우저 820px와 설계 도구의 820px 미리보기에서 같은 화면 구조를 제공한다. 스튜디오 채팅은 화면 높이에 맞춰 정리하고 메시지 영역 안에서 스크롤한다.
홈의 라이브 예시 카드 8개는 화면 폭을 이유로 숨기지 않는다. 이어보기 4개는 가로 레일 안에 유지한다. 화면 전체 가로 스크롤과 탭·이어보기 내부의 의도된 가로 스크롤을 구분해.
확대 보기는 시청 화면 안의 동작이다. 다른 페이지로 이동했을 때 사이드바가 계속 축소되거나 새 페이지의 배치에 확대 보기 스타일이 누수되지 않게 한다.

4. 보호할 구현

기존 영상 요소, 재생·음량·DVR·라이브 복귀·PiP·전체 화면·확대 보기와 원본 화질 메뉴의 모양·옵션·자동/수동 제어를 유지한다. v3.1의 기술 표기 제거는 방송 정보 모달과 영상 바깥 메타데이터에 한정한다. 새 video 요소나 별도 플레이어로 바꾸지 마.
F.watch, F.wirePlayer, preserved-player/ 및 현재 앱의 캡처·인코딩·전송 경로는 이번 작업 대상이 아니다. 실제 work/·native/·server/ 소스도 제외했다.
PLAYER_PRESERVATION.json의 8개 파일은 시안 당시 원본 참고 자료의 해시 비교 범위다. 이 비교가 현재 실제 앱 전체의 무변경 검증을 대신하지 않는다. reference/·reference-v05/·preserved-player/·기존 해시를 덮어쓰거나, 이후 사용자가 승인한 기능 변경을 되돌리지 마.
계정·방송 준비·후원 초안은 로컬 시안 상태다. 실제 OAuth·결제·권한·통계·방송 세션이 연결됐다고 보고하지 마. 기존 플레이어 상태·화질·음량·DVR 위치·채팅 초안을 메뉴나 모달 이동 때문에 초기화하지 않게 연결한다.

5. 파일과 로드 순서

최신 확장은 dist/design-v31-states.js/.css, dist/design-v31-viewer.js/.css, dist/design-v31-layout.js/.css다. 기존 v3 공통·계정·스튜디오·컴포넌트 파일 위에서 동작한다.
현재 index.html의 의존 순서를 유지해. 핵심 후반 순서는 다음과 같다.
design-v3-runtime.js → design-v31-states.js → design-v31-viewer.js → design-v31-layout.js → design-events.js
states와 viewer는 기존 기본 렌더러·모달 뒤에 로드하고, layout은 그 결과 위에서 작동하게 한다. 관련 CSS도 기존 스타일 다음에 현재 순서대로 로드한다.
기존 build-design.mjs나 build-board*.mjs를 단독 실행해 최신 dist/index.html·board-v3.html·확장 로드 순서를 덮어쓰지 마. 재생성이 필요하면 v3.1 파일과 의존 순서를 보존하도록 생성 절차를 먼저 통합하고 검증해.
board-v3.html 주소는 유지하며 시안 버전은 3.1이다. 새 주소를 만들어 기존 검토 링크를 깨뜨리지 마.

6. 검증과 인계 완료 기준

검증 결과 정리 위치: verification/v31/
검색어 수정·오류 재시도·로딩 접근성, 탭 전환·포커스·가로 스크롤, 방송 정보·공유의 선택 방송 일치와 원래 화면 복귀를 확인한다. 다시보기·방송 종료·빈 메타데이터에서 잘못된 LIVE·시청자 수·기술 표가 남지 않아야 한다.
320·390·820px와 넓은 데스크톱에서 홈 전체 카드·이어보기 레일·스튜디오 채팅 높이를 확인하고 실제 820px와 미리보기 820px를 비교한다. 확대 보기 후 다른 페이지로 이동했을 때 메뉴 배치도 점검한다.
원본 플레이어 보존 검사와 새 UI 검증은 구분해 기록한다. 검사 건수와 통과율은 최종 검증 결과가 확정된 뒤 보고한다. 이 문서에는 확정 전 숫자를 넣지 않는다.
기존 58개 화면·150개 기능 ID와 매핑을 유지했다. 이번 상태·배치 보완이 모든 화면·정책·서버 기능의 상세 완성을 뜻하지 않는다. 시안 렌더 확인을 실제 모바일 재생, 동시 시청 1,000명, 자동 화질, OAuth·결제·네트워크 성능 검증으로 보고하지 마.
완료 보고에는 변경한 UI 범위, 실제로 검증한 내용, 원본 유지 결과, 미확인 항목을 구분해서 적어줘.
