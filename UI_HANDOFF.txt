FRAME Console UI 0.5 인계

사용자 요청에 따라 UI는 Codex에서 수정했고 실제 캡처·송출·수신 서버 기능은 Claude가 이어서 구현한다. 이번에 변경한 UI가 새 기준이다. 기존 native/ C++ 소스, deps/, 실행 중인 영상 서버와 기존 배포 exe는 이 UI 작업에서 변경하지 않았다. 새 UI를 넣은 exe 빌드와 배포는 Claude의 남은 작업이다.

UI 변경 사항
큰 제목 ‘화면 송출’, ‘스트림 수신’과 시작·연결 버튼 옆 상태 배지를 제거했다.
수신 첫 화면을 영상 목록으로 구성했다. 썸네일, 프로필 아이콘, 송출명, PC 이름을 하나의 흰색 카드에 넣었다. 검색, 목록 새로고침과 수동 연결을 제공한다. 방송 선택 전에는 빈 플레이어를 표시하지 않는다.
송출자도 연결 설정에서 IP, 스트림 ID, 송출·시청 포트를 직접 수정할 수 있다. 수신자의 수동 연결 창에는 IP, 스트림 ID와 시청 포트가 있다. 수신 포트 입력을 기존 클라이언트 연결 URL에 반영했다.
송출 화면 오른쪽은 본인 방송의 채팅 영역이다. 기존 ‘영상 및 오디오’와 ‘시청 주소’는 송출 시작 버튼 바로 왼쪽의 ‘송출 설정’ 버튼으로 여는 하나의 모달에 모았다. 기존 필드·ID·볼륨·복사·시청 기능을 유지하며 설정 모달에서 Enter를 눌렀다고 방송을 시작하지 않는다. 송출 IP·포트용 연결 설정 버튼과 모달은 유지했다.
송출자와 수신자가 사용하는 채팅 컴포넌트는 동일하지만 방 상태·메시지·초안·전송 확인은 sender/viewer 문맥별로 분리했다. 다른 방송을 시청하다 송출 화면으로 돌아와도 본인 방송 채팅과 초안이 유지된다. 설정 모달에 맞춰 자체 선택 메뉴를 열린 dialog 안의 포털로 표시하도록 수정했다.
프로그램 창 / 전체 화면 탭과 모니터 선택 카드를 추가했다. 기존 프로그램 창 선택 메시지는 유지했다.
플레이어에 과거 구간 탐색 재생바, 실시간 복귀 버튼과 PiP 버튼을 준비했다. 실제 DVR 데이터가 없으면 탐색 재생바를 숨긴다. PiP는 실제 video와 브라우저 지원이 있을 때 활성화된다.
사이드바에서 ‘스트리밍’ 문구를 제거하고 메뉴를 ‘송출 하기’, ‘전체 수신 목록’으로 표시한다. 기본 사이드바 폭은 220px로 목록과 상세 화면에서 동일하다. ‘확대 보기’를 명시적으로 눌렀을 때만 72px 아이콘 메뉴로 축소한다. 영상은 원본 비율을 유지하고 잘라내거나 늘리지 않는다.
영상 상세에서 전체 수신 목록 메뉴의 선택 상태를 해제하고, 이 메뉴 클릭으로 재생을 정리한 뒤 전체 목록으로 돌아간다. 상세 상단의 목록 이동·송출명·시간과 연결 설정·수신 종료 버튼은 제거했다. 송출명·경과 시간 등 영상 정보는 상단 버튼으로 여는 모달에 있다. 수동 연결은 전체 수신 목록에서, 송출 연결 설정은 송출 화면에서 제공한다.
채팅은 상세 진입 시 기본으로 열린다. 닫거나 다시 열 수 있고 좁은 창에서는 오버레이로 표시한다. 글자 수 표시는 제거했지만 입력 길이 제한은 유지했다. 이름 설정 모달과 브라우저별 표시 이름 저장을 추가했다. 채팅 서버·인증·실제 메시지 전송은 연결하지 않았다.
영상 영역 클릭으로 일시정지·이어 보기를 전환한다. 버튼·슬라이더·화질 메뉴 클릭은 재생 상태를 바꾸지 않는다. 기존 Space/K 조작도 유지한다. 수동 연결 취소 후 늦게 도착한 연결 결과가 재생을 다시 시작하지 않도록 요청 세대 검사를 추가했다.
목록 상단과 고급 설정 위 구분선을 제거했다. 고급 설정의 화살표는 설정 톱니바퀴로 바꿨다. 새로고침, 연결, 화질 설정 아이콘은 인라인 SVG로 다듬었다.
Pretendard, 기존 밝은 콘솔 색상, 자체 콤보박스, 음량 슬라이더와 입력 포커스 스타일은 유지했다. 업무용 표현인 송출·수신을 유지했다. 공적인 용어표는 대화 중 비교안이며 모든 항목을 일괄 적용한 것은 아니다.

파일과 버전
work/console-template.html은 실제 DOM이다. work/console-ui.css는 0.5 추가 스타일, work/console-ui.js는 목록·모달·탐색 컨트롤의 표현 계층이다.
work/console-ux.js는 이미 있던 네이티브 브리지와 WHEP 수신 코드다. UI 변경에 필요한 최소 연결 지점(FrameRuntime, 이벤트, 수신 포트)을 추가했다. 기존 캡처·인코딩 C++ 코드를 새로 만들지 않았다.
work/build-console.mjs는 기존 CSS·컴포넌트와 위 파일을 묶어 outputs/index.html을 만든다. 추가 아이콘은 빌드 시 삽입·갱신한다.
reference/와 UI_LOCK.json은 이전 0.4 원본으로 보존했다. 이번 사용자 승인 변경으로 구형 검사는 현재 화면에 실패할 수 있다. 이를 숨기거나 0.4 원본을 덮어쓰지 않는다.
reference-v05/와 UI_V05_LOCK.json은 0.5 UI 기준이다. 새 검사는 0.4 reference 보존과 0.5 스타일·마크업·아이콘을 함께 확인한다. 기능 연결을 위한 JS 수정은 허용하지만 UI 구조와 스타일은 유지한다.

영상 목록 계약
work/console-ui.js는 GET /api/broadcasts를 같은 출처에서 호출한다. 응답은 다음 형태다.
{"items":[{"id":"unique-broadcast-id","title":"송출명","publisher":"PC-01","baseUrl":"http://192.168.10.20:8889","path":"screen-01","thumbnailUrl":"/thumbnails/unique-broadcast-id.jpg","width":1920,"height":1080,"fps":60,"running":true}]}
id는 방송 구분용 ID, path는 재생용 스트림 경로다. 썸네일 주소는 HTTP(S) 절대 주소 또는 현재 페이지 기준 상대 주소다. 다른 송출 PC의 썸네일은 정확한 절대 주소를 제공한다. 설정된 화질 파생 스트림을 별도 방송으로 중복 나열하지 않는다.
window.FrameUI.setBroadcasts(items)로 직접 목록을 갱신할 수도 있다. 기본 GET이 아직 구현되지 않은 현재 서버에서는 목록 오류와 수동 연결이 표시된다. 실제 송출 목록이 구현됐다는 뜻이 아니다.
WebView2의 가상 호스트(frame-console.example)는 실제 HTTP API 서버와 다르다. 네이티브 앱에서는 실제 목록 서버 주소를 설정해 호출하거나 검증된 브리지로 목록을 전달하고 setBroadcasts를 호출해야 한다. 정적 가상 호스트에 /api/broadcasts 파일이 있을 것이라고 가정하지 않는다.
카드 선택은 기존 info/WHEP 경로에 연결한다. 수동 연결과 기존 /<stream-id> 직접 수신 주소도 유지한다. 다른 출처 연결에 필요한 CORS와 권한은 서버에서 검증해야 한다.

모니터 계약
document의 frame:request-monitors 이벤트에서 실제 모니터 목록을 요청한다.
window.FrameUI.setMonitors([{id:"stable-monitor-id",number:1,width:2560,height:1440,scale:125,primary:true,thumbnailUrl:"http://server/monitor-1.jpg"}])로 목록을 공급한다.
thumbnailUrl은 선택 사항이며 없으면 모니터 번호가 표시된다. 현재 모니터 실제 열거·캡처는 연결하지 않았다.
document의 frame:select-monitor 이벤트 detail.id가 선택 결과다. Claude는 이 이벤트를 검증된 네이티브 명령에 연결하고 성공 후 기존 source 이벤트와 미리보기를 갱신한 뒤 source-dialog를 닫아야 한다. 기존 selectWindow 명령을 모니터 ID로 잘못 호출하지 않는다.

DVR 계약
window.FrameUI.setTimeline({startMs:0,endMs:10800000,positionMs:600000,mode:"history"})가 표시 상태를 갱신한다. 시간 단위는 밀리초이며 같은 방송의 동일한 시간축을 사용한다. 첫 녹화 시점과 실제 재생 가능한 끝을 공급한다.
mode는 live 또는 history다. history에서 실시간 버튼이 활성화된다. 데이터가 없거나 유효하지 않으면 setTimeline(null)로 탐색을 숨긴다.
document의 frame:seek 이벤트 detail.positionMs는 이동 요청이다. frame:live 이벤트는 최신 라이브 복귀 요청이다. 현재 UI는 이 이벤트를 발생시키며, 실제 녹화 재생과 WebRTC 전환은 아직 연결하지 않았다.
실제 전환 성공 후 서버·미디어 상태에 맞게 setTimeline을 호출한다. 재생바 숫자만 바꾸어 영상 이동 성공으로 처리하지 않는다. 재생 불가능한 구간·실패·보관 범위 변경도 처리한다.

런타임 연결 지점
window.FrameRuntime.connect(optionalBaseUrl), disconnect(), validate(report), view(name), chooseSource(), notify(message)를 제공한다. connected, connecting, remote, running, video, stream은 읽기 전용 getter다. 임의로 연결 성공 상태를 덮어쓰지 않는다.
document의 frame:receiver 이벤트는 connected, heading, description을, frame:media는 video 교체를 알린다. 기존 네이티브 이벤트와 WHEP 로직은 console-ux.js에 남아 있다.
frame:connecting은 실제 연결 요청이 시작됐음을, frame:view는 현재 송출/수신 화면 전환을 알린다.
frame:sender-state는 실제 송출 시작·종료를 알리며 detail.running과 시작 시 status를 제공한다. 아직 실제 채팅 서버와 연결하지 않았다. 단순히 running=true라는 이유만으로 채팅 서버 연결 성공을 표시하지 않는다.

채팅 계약
현재 채팅 UI는 서버에 연결되지 않았다. 기본적으로 전송 입력을 비활성화하며 UI만으로 가짜 연결 성공이나 메시지 전달을 만들지 않는다.
window.FrameUI.setChatState({connected:true,canSend:true,broadcastId:"actual-broadcast-id",displayName:"서버에서 확정한 이름"})가 실제 방 연결과 전송 권한을 반영한다. 방송이 바뀌면 방 ID를 반드시 갱신한다. 오류는 error 문자열로 공급할 수 있다.
window.FrameUI.setMessages([{id:"message-id",broadcastId:"actual-broadcast-id",author:"표시 이름",text:"내용"}])는 초기 기록을 공급한다. appendMessage(item)는 서버가 확정한 새 메시지를 추가한다. HTML로 해석하지 않고 텍스트로 표시하며 최근 200개까지만 화면 메모리에 유지한다.
document의 frame:send-message 이벤트 detail은 {context,broadcastId,displayName,text,clientId}다. context는 sender 또는 viewer다. 클라이언트 ID와 입력한 표시 이름은 사용자 인증이 아니다. 서버 수신 확인 후 window.FrameUI.ackMessage({clientId,ok:true},context)를 호출한다. 실패 시 {clientId,ok:false,error:"원인"}을 전달한다. 전송 버튼 클릭만으로 메시지가 대화에 표시되거나 성공 처리되지 않는다.
frame:set-chat-name 이벤트 detail.name은 사용자 이름 변경 요청이다. UI는 브라우저별 이름을 기억하며 최초 전송 시 이름이 없으면 설정 모달을 연다. 서버는 이름을 검증·확정하고 이 사용자의 방 세션에만 적용해야 한다. 인증 사용자와 표시 이름을 구분하고 거부·정규화 결과도 실제 UI에 반영한다.
이름 요청에도 context와 broadcastId가 포함된다. UI의 이름 설정은 동일 사용자의 브라우저 선호값이며 다른 사람의 이름이나 방의 권한을 변경하지 않는다.
기존 setChatState(data), setMessages(items), appendMessage(item), ackMessage(data)는 기본적으로 viewer 문맥을 사용하며 두 번째 인수로 context를 명시할 수 있다. 송출자 전용 별칭 setSenderChatState(data), setSenderMessages(items), appendSenderMessage(item), ackSenderMessage(data)도 제공한다.
실제 서버는 송출 시작·등록 시 본인 방송의 ID와 채팅 정보를 송출자 전용 API에 전달해야 한다. source 채팅을 현재 시청 중인 다른 방송의 ID나 runtime.stream만으로 연결하지 않는다. 송출자가 채팅만 보려고 자기 영상을 WebRTC로 다시 수신할 필요는 없다.
frame:chat-context는 보이는 화면의 문맥 전환을 알린다. 화면이 바뀌어도 송출 중인 본인 방송의 채팅을 다른 방으로 바꾸거나 기록·초안을 지우지 않는다. 송출자와 시청자가 같은 방송을 보는 경우 서버의 같은 방에 연결하되 메시지·전송 확인을 중복 처리하지 않는다.
Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter를 전송으로 처리하지 않는다. 연결 끊김·권한 없음은 실제 상태에 맞게 입력을 비활성화한다. 과거 영상을 보는 동안에도 이 패널은 현재 방의 실시간 채팅이다. 녹화 영상 시점과 채팅 기록 동기화는 이번 UI에 포함하지 않았다.

검토 데이터
Codex 작업 폴더의 localhost:5317 미리보기는 review=1일 때만 독립된 예시 데이터와 가상 브리지를 사용한다. 이는 화면 검토 전용이며 실제 송출·성능 검증이 아니다.
검토 데이터 파일과 썸네일은 이 frame 프로젝트에 넣지 않았다. 운영 UI에는 예시 방송, 가상 연결 성공, 고정 3시간 DVR 데이터가 없다. Claude는 로컬 검토용 코드를 실제 앱으로 복사하지 않는다.
