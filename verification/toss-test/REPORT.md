# 홈 메뉴 글꼴 복원 및 Toss 테스트 결제 검증

검증일: 2026-11-11. 이 PC의 Spring·MediaMTX와 Vite 개발 서버, headless Edge에서 확인했다. 커밋·푸시·배포는 하지 않았다.

## 변경

- 스튜디오 전용 메뉴 글꼴 덮어쓰기를 제거했다. 홈과 스튜디오 모두 기본 15px/550, 선택 항목 700, 행 높이 46px, 아이콘 22px를 사용한다. 기존 색감·메뉴 분류·콘텐츠 여백을 유지했다.
- 후원 신청에서 서버 주문을 만든 뒤 공식 Toss SDK v2 결제창을 연다. 토스 결제창에서 결제수단을 선택하고, 인증 결과를 Spring에서 승인·검증한 뒤 완료 화면과 실제 주문 내역을 표시한다.
- 취소·오류 시 작성한 금액과 동의를 복원한다. 같은 작성 내용의 재시도는 기존 주문을 사용한다. 서버는 금액·주문 소유자·결제 키를 검증하고, 승인 전 안정적인 멱등키를 저장한다.
- 시크릿 키와 보안 키는 저장소 밖 로컬 설정에서 Spring으로만 전달한다. 브라우저에는 공개 클라이언트 키만 제공한다.

## 실제 Toss 테스트 결제

`http://127.0.0.1:5360/_frame/channel/spring`의 후원하기에서 5,000원 메시지 후원을 신청했다. 실제 Toss 테스트 결제창을 열고, 토스가 제공하는 퀵계좌이체 데모의 기본 테스트 휴대폰번호와 화면에 안내된 테스트 비밀번호를 사용했다. 개인 카드·계좌·휴대폰 정보는 입력하지 않았다.

1. 결제창 닫기 후 금액 5,000원과 동의 체크가 복원됐다. 다시 신청해도 주문 수와 주문번호가 유지됐다.
2. 카드사 인증 화면 진입과 취소 후 작성 화면 복원을 확인했다. 카드사 개인 인증은 진행하지 않았다.
3. 공식 퀵계좌이체 데모에서 인증·결제를 완료했다. 브라우저의 Spring 승인 요청은 1회, 응답은 HTTP 200이었다.
4. Spring 주문이 `DONE`, `KRW`, 5,000원, 결제수단 `계좌이체`로 저장됐다. 완료 화면과 결제 내역에도 동일하게 표시됐다.
5. 완료 URL에는 주문번호만 남고 `paymentKey`와 금액은 제거됐다. 새로고침은 저장된 주문을 조회하며 승인을 다시 요청하지 않았다.

## 추가 확인

- 1440px·390px에서 홈/스튜디오의 글꼴 크기·굵기·행 높이·아이콘 크기가 같았다. [측정값](sidebar-font-result.json), [스튜디오 화면](studio-fonts.png)
- 실제 서버 주문과 다른 금액 4,999원을 보내면 HTTP 400 `AMOUNT_MISMATCH`로 거절됐다.
- 잘못된 성공 콜백은 승인 요청이나 완료 표시를 만들지 않았다. 취소 콜백은 취소 상태를 표시하고 임의의 쿼리 메시지를 그리지 않았다.
- 390px 완료 화면에 가로 넘침이 없었다. [모바일 화면](payment-mobile.png)
- 프론트 `typecheck`, `build`, `build:design` 통과. Spring 전체 테스트·`bootJar` 통과. 결제 관련 서버 테스트 10개 통과.
- 서버 테스트는 모의 HTTP 서버로 중복·동시 승인, 재시작 후 멱등키, 잘못된 성공 응답, 저장 실패, 큰 정수 금액, 느린 응답 기한 등을 확인했다. 실제 Toss 승인 1건과 구분한다.
- 로컬 프록시의 Host·Origin·경로·메서드 제한 12개 검사를 통과했다. 소스 185개, 빌드 파일 161개, JAR 항목 258개, 로그 2개에서 실제 비밀 키가 발견되지 않았다.

## 적용 범위와 남은 부분

이 연결은 이 PC의 개발 서버와 테스트 결제를 위한 것이다. 계정·채널 화면은 기존 DEV/design 구성에 속하며, 공개 시청용 프로덕션 번들에 결제 화면을 배포한 것은 아니다. 로컬 프록시의 운영자 인증을 사용하므로 인터넷 서비스의 구매자별 인증·권한은 별도 구현해야 한다.

환불·웹훅·실제 정산·음성/영상 후원 재생은 이번 PG 연결에 포함하지 않았다. 휴대폰 실기기·다른 브라우저의 결제 인증도 미검증이다. 생성 후 결제하지 않은 테스트 주문은 결제 확인 대기로 남는다.

제공받은 `docs` 키는 공유 체험 키다. 본인 개발자센터에서 테스트 거래내역을 관리하려면 본인 상점의 같은 세트 테스트 키로 바꿔야 한다. [Toss 공식 FAQ](https://docs.tosspayments.com/resources/faq)

설정·API·오류 처리: [테스트 결제 연결 문서](../../deploy/TOSS_TEST.md). 테스트 결제와 영수증의 차이: [Toss 공식 테스트 환경](https://docs.tosspayments.com/guides/v2/get-started/environment).
