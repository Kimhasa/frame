# OBS 기본 송출 전환과 로컬 실제 연동

2026-11-11 KST. 기존 C++ 앱·설치된 OBS 프로필을 변경하지 않았다.

## 구현

- OBS의 H.264+AAC RTMP/RTMPS 입력을 MediaMTX가 받고 Spring이 자동으로 방송 목록에 등록한다. 송출 PC의 별도 등록 프로그램이나 브라우저 유지가 필요하지 않다.
- `obs-*` 경로의 단일 AAC DVR 규칙과 기존 네이티브 Opus+AAC 규칙을 구분한다.
- 짧은 재접속은 같은 방송 ID를 유지한다. 종료 유예 이후 새 송출은 새 ID를 받고 이전 링크는 새 방송을 열지 않는다.
- 송출자 API는 명시적으로 단독 소유한 경로의 토큰만 허용하고 `no-store`로 응답한다.
- `server/obs-local.mjs start|status|stop`이 저장소 밖 설정과 키를 유지한다. 로컬 MediaMTX·Spring은 루프백에만 바인딩한다.
- Vite 개발 서버는 로컬 설정을 발견하면 실제 시청 어댑터와 고정 경로의 관리 프록시를 연결한다. 토큰은 클라이언트 환경변수·소스·브라우저 저장소에 넣지 않는다.
- 방송 준비 화면은 실제 주소·키, 수신 영상, 채팅, 제목 저장, 측정값을 사용한다. 모르는 FPS는 `—`로 표시한다. 영상 미리보기는 음소거로 시작한다.
- 공개 전 수신과 공개 시작을 나누는 가짜 버튼은 없다. OBS에서 송출을 시작하면 방송이 공개되고 OBS에서 멈추면 유예 후 종료된다. 실제 모드에서 지원하지 않는 비공개 설정·키 재발급 조작은 제공하지 않는다.
- 안내성 예시 문구를 화면에서 제거했다. PG 미연동 후원·환불·취소와 개발자 키 발급·계정 복구는 성공 상태를 생성하지 않는다.

실제 UI 검사는 루프백 RTMP로 시험 영상(640×360, 30fps)과 사인 음성(AAC)을 보내 headless Edge에서 재생했다. 실제 영상 크기·재생 시간·AAC 디코딩, WebSocket 채팅 반영, 서버 제목 저장, 공유 링크의 방송 ID, 송출 중지 후 대기 복귀를 확인했다. 시험 송출은 종료했고 로컬 수신 서버는 OBS 사용을 위해 실행 상태로 유지했다.

추가 상태 검사에서 저장 중 편집·닫기·Escape를 잠그고 8초 후 오류에서 복구하는 것을 확인했다. 방송이 시작돼도 열린 편집창과 미저장 입력을 유지한다. 클립보드가 거절되면 실제 값을 선택하며, 키는 다시 숨길 수 있다. 후원 제출은 입력을 보존하고 거래 성공으로 바꾸지 않는다.

보안 확인: 정상 관리 요청은 200/no-store, 외부 Origin·Host 및 임의 하위 경로는 403, Vite 파일 경로로 비밀 설정을 읽는 요청은 404였다. 공개 시청 응답과 MediaMTX·Spring 로그에 송출 토큰이 없었다.

기존 회귀 검사의 재시도 항목은 고정 6초 대기를 실제 두 번째 시도까지 최대 15초 기다리는 방식으로 수정했다. 401 거절·로컬 송출 유지·재시도 횟수 조건은 유지했다. 수정 전 첫 실행은 이 시점 검사 한 건만 실패했고, 수정 후 전체 108개를 통과했다.

## 실행과 범위

현재 페이지: `http://127.0.0.1:5360/_frame/studio/broadcast`. OBS 설정의 서비스는 사용자 지정으로 선택하고 화면의 송출 주소·키를 복사한다. 서버 재실행과 상세 설정은 [deploy/OBS.md](../../deploy/OBS.md)를 따른다.

OBS GUI 자체의 송출과 인터넷 공개는 검사하지 않았다. 프로토콜 송출 검사는 FFmpeg로 했으며, 사용자의 OBS 설정이나 실제 화면을 캡처하지 않았다. 로컬 개발 연결은 인터넷 서비스의 계정·채널 권한 인증을 대신하지 않는다. 계정·여러 관리 화면의 제품 API와 PG 연동은 남아 있다. Spring 재시작 시 메모리의 방송 ID·제목이 초기화되는 제한도 있다.
