# 송출 대상 선택 · 창 미리보기 개선 보고 (CLAUDE_WINDOW_PREVIEW_ADDENDUM.txt)

측정일: 2026-10-28. 모든 수치는 이 PC 한 대에서 실제 실행한 결과입니다.
- 앱: FrameConsole 0.5.0 개발 빌드, WebView2 155.0.4283.62(Evergreen, 하드웨어 가속 기본값)
- PC: Windows 11 25H2(26200), 캡처 장치 NVIDIA GeForce RTX 3060 Laptop GPU(내장 Intel UHD 함께 있음), 3840×2160 모니터 2대(주 175%, 보조 150%)
- 변경 전은 14:23 배포 zip의 exe, 변경 후는 현재 빌드입니다. 같은 시험 창과 같은 상태로 비교했습니다.

사용자 창(Discord·Chrome·Claude·MapleStory 등)은 실행 파일 이름, 상태, 시간만 기록했습니다. 제목과 썸네일 이미지는 저장하지 않았습니다.

## 확인한 원인
**코드와 실측으로 확인한 것**
- 이전 `ListWindows`는 최소화된 창을 건너뛰었습니다(코드).
- 최소화된 창은 WGC가 2초를 기다려도 프레임을 하나도 보내지 않습니다(실측, `tools`의 probe).
- 사용자가 지목한 창 가운데 이 PC에서 실제로 실패한 것은 모두 최소화된 창이었습니다. 변경 전 데스크톱 측정에서 7개 창 중 MapleStory·Discord·모션 테스트(최소화) 3개가 아이콘으로만 남았습니다. 보이는 Chrome·Claude는 0.1~0.26초 만에 성공했습니다.
- 앱이 캡처 제외(SetWindowDisplayAffinity)를 설정한 창도 WGC 프레임이 오지 않습니다(실측).
- 기본 설정 Chromium 창(Edge·Chrome·Electron)은 가려져 있어도 WGC 첫 프레임이 20ms 안에 옵니다. 다만 내용은 가려진 순간에 멈춘 상태입니다. 최소화하고 몇 초가 지나면 그린 내용을 비워서 DWM 썸네일이 완전히 0(검정)이 됩니다(실측).

**확인하지 못한 가설**
- 사용자가 이전에 본 Chrome·Claude 실패도 그때 최소화돼 있었을 것이라는 추정은 직접 재현하지 못했습니다.
- Discord 선택창의 내부 구현은 확인하지 않았습니다.

## 구현
- **네이티브 `WindowThumbnails`** (`native/src/thumbnails.*`)
  - 목록을 먼저 보내고 별도 작업 스레드에서 이미지를 채웁니다.
  - 보이는 카드와 선택한 창을 먼저 처리하고, 동시 처리는 2개입니다.
  - 첫 프레임은 이벤트로 기다립니다(1초). 시도는 3회이고 재시도 간격은 250/750ms이며, 두 번째 시도는 DWM 경로입니다. 창마다 전체 기한은 5초이고, 기한이 시도 횟수보다 우선합니다.
  - 최소화된 창은 cloak된 도우미 창에 DWM 썸네일을 그려 캡처합니다. 결과가 모두 0이면 이미지를 보여 주지 않습니다.
  - 캡처 제외 창은 시도하지 않습니다.
  - 닫힘·숨김·최소화·복원을 0.5초마다 확인합니다.
  - 목록 세대와 요청 ID로 늦게 도착한 결과를 버립니다.
  - 60초 캐시는 '이전 화면'으로 구분해 표시합니다.
  - 시도마다 진단 로그(`[thumb]`)를 남깁니다. 단계·오류·대기열 시간/시도 시간/작업 전체 시간·경로가 들어 있고, UI 디코드 결과도 함께 기록합니다.
  - 설정은 `windowPreview`로 바꿀 수 있고, 결함 주입은 `FRAME_CONSOLE_THUMB_FAULT`(시험 전용)로 합니다.
- **앱 아이콘** (`native/src/window_icon.*`)
  - 조회 순서: WM_GETICON(100ms 제한), 클래스 아이콘, 실행 파일 아이콘. 결과는 WIC 투명 PNG로 만들고, 크기는 24px × 배율입니다.
- **선택창** (`work/source-preview.css`, `work/console-ux.js`)
  - 폭은 min(1120, 보이는 폭 − 48)px, 높이는 90% 이내이고, 목록만 스크롤됩니다.
  - 썸네일은 16:9 contain으로 표시하고, 생성 크기는 카드 폭 × 배율입니다.
  - 제목 행은 아이콘 24px + 16px/550 제목이며 한 줄 말줄임입니다.
  - 상태 문구와 재시도 버튼은 카드 button 밖에 형제 요소로 두었습니다(중첩 없음).
- **UI 기준**: `UI_V061_ADDENDUM.json`와 `tools/verify-ui-v061.mjs`. 기존 잠금과 해시는 바꾸지 않았습니다.

## 결함 주입 (실제 실패가 아니라 시험 스위치로 만든 지연·실패)
- **drop**: '응답이 늦습니다' → 4.0초에 최종 시간 초과 → 재시도 버튼. 수동 재시도와 키보드(Tab → Enter) 재시도가 됩니다. 재시도 중 닫으면 작업이 끝나고 이후 시도가 없습니다(로그).
- **delay 1.5초**: 두 번째 시도에서 성공합니다.
- **corrupt**: UI 디코드 실패가 '미리보기를 가져오지 못했습니다'로 표시되고 네이티브 로그에도 남습니다.
- 모두 `states-fault-*.json`에서 PASS입니다.

## 상호작용·레이아웃 (`states-live.json`, `layout-*.json`, `screens/`)
- **목록이 열린 상태에서의 변화**
  - 최소화하면 이미지는 그대로 두고 '최소화된 창'을 표시합니다.
  - 복원하면 새 이미지로 바뀌고 상태 문구가 사라집니다.
  - 선택한 창을 닫으면 '창이 닫혔습니다'가 뜨고 카드가 비활성되며 선택이 풀립니다.
- **40ms 안에 닫았다 다시 열기**: 이전 목록 작업을 종료합니다.
- **선택만으로는 송출이 시작되지 않습니다.**
- **실제 창 크기(175%)**
  - 400×480: 1열이고, 버튼이 보입니다.
  - 800×600: 2열, 카드 330px입니다.
  - 1280×720, 1440×1000, 1920×1080: 1120px 선택창에 카드 521px입니다.
  - 가로 스크롤 0, 목록만 스크롤됩니다.
- **실제 배율 변경**: 앱 창을 150% 모니터로 옮기면 썸네일은 790×444, 아이콘은 36px로 바뀝니다.
- **에뮬레이션(WebView 뷰포트·배율만, OS 배율 아님)**: 2560×1440@100%, 1920×1080@125%·@200%, 1280×720@100%에서 PASS입니다.
- **가장자리 색 띠 창**(16:9·4:3·세로·정사각·울트라와이드)
  - 생성 이미지에 네 가장자리가 모두 있고, 비율 오차는 1.5% 미만입니다.
  - 16:9는 영역을 채우고(1.8px 이내), 나머지는 contain 여백이 생깁니다.
- **제목 행**
  - 긴 한글 제목은 한 줄 말줄임으로 줄고, 전체 제목은 툴팁과 접근성 이름에 남습니다.
  - 같은 제목의 창은 'probe.exe 1/2'로 구분됩니다.
  - 아이콘 없는 창과 응답 없는 창은 기본 아이콘을 씁니다. 아이콘 25개 조회에 14ms가 걸렸습니다.
- **실제 앱 아이콘**: MapleStory·KakaoTalk·Chrome(프로필 배지)·Claude·ChatGPT·Discord·Edge·NexonPlug가 맞게 나왔습니다(`screens/icons-w1440.png`, 제목 없음).
- **플레이어 바깥 틀**: 0.6.1 스타일을 실제로 제거한 상태와 비교해도 송출 미리보기 틀 크기가 같습니다.

## 자원·송출 영향 (`cost-*.json`, `concurrency-*`, `broadcast-impact.json`)
- **목록 1회당 FrameConsole CPU 시간**
  - 같은 14개 창, 480px 이미지: 변경 전 116ms, 변경 후 97~106ms.
  - 최종(24개 창, 916px 이미지): 266ms.
  - GPU 3D 사용률은 최대 1.4%입니다.
- **핸들 증가(목록 1회당)**: 변경 전 +11개, 변경 후 +1.5개입니다. 개인 메모리 증가는 15회에 약 4MB였습니다.
- **동시 처리 수 비교(목록 완료 시간)**: 1개는 0.89~0.93초, 2개는 0.30~0.38초, 4개는 0.30~0.40초였습니다. 4개는 CPU를 더 쓰고 빠르지 않아서 2개로 정했습니다.
- **송출 중 영향**
  - 송출 중에는 대상 선택이 잠겨 있어 미리보기 작업 자체가 없습니다.
  - 시험 경로로 목록을 강제로 3번 열어도 송출 60fps와 원본 비트레이트는 변하지 않았습니다.
  - 큰 송출 미리보기(1280×720)와 실제 수신 영상(1920×1080 재생)은 따로 확인했습니다.

## 남은 제약
- 최소화된 창의 DWM 화면에는 앱이 직접 그린 제목줄(Chromium 계열)이 포함될 수 있습니다.
- 가려진 Chromium 창은 가려진 순간의 화면입니다. 송출도 같습니다.
- ChatGPT 창 아이콘은 흰색이라 밝은 카드에서 잘 보이지 않습니다(실제 아이콘).
- 목록 1회당 핸들 약 1.5개가 남습니다(원인 미확인, 이전 대비 87% 감소).
- `verify-ui-v06`은 일시 중단된 모바일 작업의 `mobile-ui.css` 변경 때문에 아직 실패합니다. 0.6.1 자체 검사는 통과합니다.
