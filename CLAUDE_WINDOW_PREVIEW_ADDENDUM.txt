1. 기존 디자인과 기능 유지

데스크톱의 2열 카드 배치, 선택 테두리, Pretendard, 밝은 테마와 기존 색상, 선택/취소 동작을 최대한 유지해. React/Electron 전환이나 전체 UI 재디자인은 하지 마.
허용 변경은 송출 대상 선택 모달의 폭 확대와 화면 크기에 맞는 높이·스크롤 조정, 그에 따른 카드·썸네일 크기와 비율 조정, 영역 안의 짧은 상태·실패 이유와 작은 재시도 조작, 썸네일 아래의 앱 아이콘·창 제목 행이야. 새 설명 카드, 큰 경고 배너, 긴 기술 문구나 반복 토스트를 추가하지 마.
이전 지시의 ‘모달 크기 유지’는 이번 요청으로 해제해. 기존 색상과 컴포넌트 스타일을 유지하면서 선택창과 미리보기를 넓히라는 명시적 UI 변경 허용이야.
Discord 참고 이미지에서는 미리보기와 앱 아이콘·제목의 읽기 쉬운 구성을 참고해. 어두운 테마, 기기 탭, 게임 카테고리나 하단 화질 설정을 그대로 가져오지 마.
이 작업은 ‘송출 대상 선택’의 카드 미리보기에 관한 것이야. 실제 송출·시청 플레이어의 고정 바깥 틀, 출력 해상도, 제목 표시줄 제외와 원본 비율 유지 동작은 보존해. 대상을 선택하는 것만으로 송출을 시작하지 마.

2. Discord에서 보이는 창을 FRAME에서도 표시하기

사용자는 같은 PC에서 Discord의 화면 공유 선택창에는 미리보기가 보이는데 FRAME에서는 Discord·Chrome·Claude 등의 일부 창이 기본 아이콘으로 남는 현상을 확인했어. 같은 대상 창과 같은 최소화·가려짐 상태에서 두 프로그램을 비교해.
대기시간과 오류 문구만 바꾸고 끝내지 마. Discord에서는 보이는데 FRAME에서 실패하는 일반 창은 우리 구현의 호환성 문제로 보고, 원인 단계와 미리보기 획득 경로를 개선해줘.
이전 구현은 최소화된 창을 건너뛰고 임시 WGC 세션의 첫 프레임을 약 400ms만 기다렸어. 현재는 WindowThumbnails, native/src/thumbnails.cpp, work/source-preview.css와 상태·재시도 처리가 추가되어 있으므로 최신 구조를 확인하고 보완해. 예전 설명 때문에 새 코드를 되돌리지 마.
WGC의 새 프레임만 기다리는 방법 외에 DWM 썸네일, 최근 성공 이미지와 필요한 지원 캡처 경로를 검토해. DWM은 JPEG를 바로 반환하는 API가 아니므로 WebView2 표시·캡처·클리핑·스크롤·선택 영역과 실제로 맞는지 검증해.
Discord의 비공개 내부 구현을 확인한 것처럼 단정하지 마. 비교는 사용자 경험과 실제 결과를 기준으로 하고, 캐시 이미지와 새 캡처 성공을 구분해. 다른 창의 이미지나 예시 이미지로 성공한 것처럼 만들지 마.
모니터를 대신 캡처해 다른 앱까지 썸네일에 섞거나, 대상 창을 자동 활성화·복원·이동하지 마. 확인된 보호 콘텐츠의 제외 정책도 존중해.

3. 대기·재시도·취소 처리

창 목록은 먼저 표시하고 썸네일을 비동기로 채워줘. 기다리는 동안 선택·스크롤·취소가 막히지 않아야 해. 화면에 보이는 카드와 선택한 창을 우선 처리해.
긴 Sleep이나 모든 창의 고해상도 반복 캡처로 해결하지 마. 프레임 도착·기한·취소를 처리하고 동시 작업 수를 제한해. GPU 공유 컨텍스트 동기화와 자원 수명을 지켜줘.
초기 검증안은 첫 프레임 대기 1초, 전체 시도 최대 3회(최초 1회+재시도 2회), 재시도 간격 250ms/750ms, 창별 전체 기한 5초야. 설정 가능하게 만들고 실제 측정 후 조정해. 전체 기한은 개별 시도보다 우선하며 큐 대기와 캡처 시간을 구분해 기록해.
일시적 시간 초과는 제한적으로 재시도하고, 종료된 창이나 확인된 비지원 상태에는 의미 없는 반복을 하지 마. 최소화 상태를 표시하고 복원 후 다시 갱신할 수 있게 해. 자동 재시도 이후에는 수동 재시도를 제공해.
모달 닫기·다시 열기·목록 갱신·창 종료 때 이전 작업을 취소·정리해. 대상 HWND/PID, 목록 세대와 요청 ID 등을 검증해서 늦은 이미지가 다른 창이나 새 목록에 붙지 않게 해.
재시도 클릭이 카드 선택·더블클릭 확인·송출 시작으로 중복 실행되면 안 돼. 카드 button 안에 재시도 button을 중첩하지 말고 키보드 접근을 유지해.
최근 이미지를 캐시하면 대상 유효성과 갱신 시점을 관리하고, 오래된 이미지를 새 실시간 화면으로 표시하지 마. 정상적으로 검은 내용을 캡처한 경우도 있으므로 검정색이라는 이유만으로 실패로 판정하지 마.

4. 상태와 실패 이유 표시

대기열·불러오는 중·성공·최소화·시간 초과·실패·창 종료 상태를 구분해. 기존 썸네일 영역 안에 ‘불러오는 중’, ‘최소화된 창’, ‘응답이 늦습니다’, ‘미리보기를 가져오지 못했습니다’, ‘창이 닫혔습니다’처럼 짧게 표시해. 성공하면 불필요한 상태 문구는 정리해.
확인하지 않은 원인을 ‘보호된 앱’이나 ‘권한 부족’이라고 표시하지 마. 자세한 설명이 필요하면 접근 가능한 툴팁 등을 사용하고 UI에 오류 코드나 내부 구현 설명을 길게 노출하지 마.
창 유효성·WGC/DWM 시작·첫 프레임 대기·GPU 변환/복사·JPEG 생성·UI 이미지 디코딩/표시 단계를 나눠 진단해. 로그에 요청/대상 ID, 상태, 실패 단계, HRESULT 등 실제 오류 코드, 경과 시간과 시도 횟수를 남겨줘.
썸네일 실패와 실제 송출 불가를 구분해. 유효한 창은 썸네일이 없다는 이유만으로 선택을 막지 말고, 선택 후 실제 캡처 실패는 기존 오류 방식으로 처리해.

5. 선택창·미리보기 확대와 좌우 여백·가장자리 잘림 정리

Discord 참고 이미지처럼 송출 대상 선택창의 가로 폭을 넓히고 2열 카드 각각의 미리보기도 함께 크게 보여줘. 제목 글자나 이미지 확대율만 올리는 것으로 대신하지 마.
데스크톱 기본 목표 폭은 1120 CSS px 정도로 시작하고 실제 화면과 비교해 조정해. 좌우에는 각각 24px 정도의 화면 여백을 확보하고, 모달은 현재 뷰포트 폭을 넘지 않게 제한해. 참고 스크린샷의 물리 픽셀 크기를 그대로 적용하지 마.
모달의 최대 높이는 뷰포트의 약 90%로 제한해. 창 목록 영역이 세로로 스크롤되고 상단 탭과 하단 선택/취소 버튼은 접근 가능한 위치에 남아 있어야 해. 가로 스크롤이나 화면 밖으로 잘린 버튼을 만들지 마. 작은 화면에서는 가용 폭을 우선하고 2열이 지나치게 좁아지는 경우에만 1열을 허용해.
현재 .source-thumb의 높이 112px와 이미지의 object-fit:contain 조합은 카드 폭이 변할 때 16:9 이미지에도 좌우 빈 공간을 만들 수 있어. CSS 여백인지 실제 캡처 잘림인지 원본 이미지와 대조해 구분해.
썸네일 영역은 넓어진 카드 폭에 맞는 기본 16:9 비율로 만들고 높이를 반응형으로 계산해. 데스크톱 2열 배치와 선택 테두리를 유지하고, 제목 행은 아래 6번 범위에서 다듬어줘. 로딩 전에 영역을 확보해 이미지 도착·실패·재시도마다 카드가 뛰지 않게 해.
생성 썸네일의 실제 해상도도 확대된 표시 크기와 DPI에 맞는지 확인해. 작은 이미지를 지나치게 늘려 흐릿해지면 생성 크기와 캐시 정책을 보완하되, 보이는 카드 우선 처리와 동시 작업 제한을 지켜 송출 성능을 해치지 않게 해.
16:9 원본은 썸네일 영역을 거의 채우면서 네 가장자리와 전체 내용이 보여야 해. 원본 비율을 보존하는 contain 방식으로 표시하고 cover·임의 확대·늘리기로 여백을 감추지 마.
세로·정사각형·4:3·울트라와이드 창은 전체 내용을 보존하는 데 필요한 여백을 허용해. 원본 비율마다 카드 크기를 제각각 바꾸거나, 모든 비율에서 여백·잘림·왜곡을 동시에 없앴다고 주장하지 마.
원본 자체의 여백, DWM/WGC 캡처 범위, 제목 표시줄 제외, 생성 이미지의 패딩, CSS padding/border/overflow를 따로 확인해. 이미지에 이미 들어간 중복 패딩은 생성 단계에서 정리하고 실제 콘텐츠는 잘라내지 마.
캡처의 source/destination rect, 클라이언트 좌표, DPI와 반올림 때문에 좌우 글자·버튼·경계가 사라지지 않는지 확인해. 장식용 테두리·둥근 모서리와 실제 콘텐츠 손실을 구분해.
work/source-preview.css의 상태·재시도 오버레이도 실제 썸네일 영역에 맞춰줘. 112px/95px 같은 독립 고정 높이를 남겨 제목을 가리거나 버튼이 엇나가지 않게 해. 스크롤·모바일 폭·DPI 변화 때 표시와 클릭 영역도 일치해야 해.

6. 앱 아이콘과 창 제목 표시

현재 카드 하단의 작은 창 제목을 ‘앱 아이콘 + 창 제목’ 한 행으로 정리해줘. 예를 들어 Claude 창에는 실제 Claude 앱 아이콘과 해당 창 제목이 함께 보여야 해. 창 제목을 전부 앱 이름으로 바꿔 같은 앱의 여러 창을 구분할 수 없게 만들지 마.
제목은 현재보다 조금 크게, Pretendard 16 CSS px와 굵기 500~600을 시작점으로 조정해. 기존 진한 본문 색상을 사용하고 실제 카드에서 가독성을 확인해. 참고 이미지의 물리 픽셀 크기를 그대로 복제하지 마.
아이콘은 24 CSS px 정도의 정사각 영역에 비율을 유지해 표시하고, 제목과 8~10px 정도 간격을 둬. 아이콘과 텍스트는 세로 중앙에 정렬하고 기존 카드 안쪽 여백을 최대한 재사용해. 아이콘을 받기 전에도 자리를 확보해서 로딩 후 제목이나 카드 높이가 움직이지 않게 해.
긴 제목은 한 줄 말줄임으로 처리하고 전체 제목은 툴팁과 접근성 이름으로 확인할 수 있게 해. min-width:0 등으로 텍스트가 카드 바깥으로 밀려나지 않게 하고, 아이콘 너비를 빼지 않는 기존 수동 말줄임 계산이 있다면 함께 고쳐줘. 일반 카드마다 실행 파일 경로·PID·중복된 부제목을 상시 표시하지 마. 같은 제목의 여러 창은 필요한 최소 구분 정보를 유지해.
아이콘은 실제 대상 창 또는 해당 앱의 Windows 아이콘을 가져와 C++ → WebView2의 기존 데이터 전달 경로에 연결해줘. 앱 이름에 따라 로고를 하드코딩하거나 외부 로고 CDN, 이모지, 썸네일 일부를 잘라 아이콘으로 사용하지 마.
WM_GETICON, 창 클래스 아이콘, 필요한 경우 실행 파일·패키지 아이콘 순의 대체 경로를 검토해. 다른 앱이 응답하지 않아 목록이 멈추지 않도록 창 메시지 조회에는 SendMessageTimeout 등의 제한을 두고 UI 스레드의 긴 동기 대기를 피해야 해. DPI에 맞는 크기, 투명 배경과 종횡비를 유지해 흐릿함·검은 배경·가장자리 잘림을 확인해.
아이콘 캐시와 늦은 응답은 창·프로세스 식별자, 목록 세대, DPI와 연결해 다른 앱의 아이콘이 붙지 않게 해. 조회·변환 중 만든 핸들과 이미지 자원은 소유권에 맞게 정리하고 빌린 공유 아이콘 핸들을 임의 해제하지 마.
아이콘이 없거나 조회가 실패하면 같은 크기의 단정한 기본 애플리케이션 아이콘을 표시해. 아이콘 실패로 썸네일이나 창 선택을 막지 말고, 미리보기 실패 상태와 앱 아이콘 조회 실패를 혼동하지 마. 재시도 조작과 제목 행이 겹치지 않고 키보드 선택과 포커스도 유지되어야 해.

7. 성능·기존 기능 보존

모달 종료와 앱 종료 시 캡처 세션·이벤트·스레드·GPU 자원·타이머를 정리해. 닫힌 목록 때문에 백그라운드에서 무제한 캡처가 계속되면 안 돼.
썸네일 개선이 송출 FPS·오디오·자동 화질·DVR·채팅에 미치는 영향을 측정해. 저사양 환경에서도 미리보기 목록을 여는 것 때문에 송출이 끊기지 않게 해.
reference/·reference-v05/와 기존 UI 잠금은 보존해. 허용된 선택 모달 폭·높이·스크롤·카드 크기·썸네일 비율·상태·재시도·앱 아이콘·제목 행 변경만 새 추가 기준과 화면 비교로 검증하고 기존 해시를 덮어써 변경 없음을 꾸미지 마. 현재 체크아웃의 최신 UI 검사도 함께 확인해.

8. 검증과 완료 보고

Chrome·Discord·Claude·게임 창과 정상 표시되는 다른 창을 시험해. 일반 표시·가려짐·최소화·복원·크기 변경·창 종료·목록 재열기·연속 재시도를 구분해. 같은 제목의 창과 정상 검은 콘텐츠도 확인해.
같은 대상에 대한 Discord 선택창, FRAME 변경 전·후의 성공 여부와 첫 이미지 시간을 비교해. 실제 앱 버전·Windows·DPI·하드웨어 가속 상태와 이미지가 새 프레임인지 캐시인지 기록해.
Chrome·Discord·Claude·게임의 실제 앱 아이콘과 창 제목이 일치하는지 확인해. 긴 한글 제목·동일 제목의 여러 창·아이콘 없는 창·응답하지 않는 창·목록 재열기와 DPI 변경에서도 정렬·말줄임·응답성을 확인해. 가능한 환경에서 100/125/150/175/200% 배율을 확인하고 시험하지 못한 배율은 따로 보고해.
넓어진 선택창을 1280×720·1920×1080·2560×1440과 작은 창 크기에서 가능한 만큼 확인해. 2열 미리보기가 실제로 커졌는지, 목록 스크롤·키보드 이동·선택/취소 버튼이 정상인지, DPI 변경 후 화면 밖으로 잘리거나 가로 스크롤이 생기지 않는지 검증해. 실제 송출·시청 플레이어의 바깥 틀은 이번 변경으로 커지거나 작아지면 안 돼.
16:9·4:3·세로·정사각형·울트라와이드 원본을 비교해. 네 가장자리에 글자·색상 표식이 있는 테스트 창으로 원본 캡처 → 생성 이미지 → 카드 표시를 확인하고 잘림·중복 여백·왜곡을 검증해.
썸네일, 선택 후 큰 송출 미리보기와 실제 수신 영상은 각각 확인해. 목록 이미지가 나오는 것만으로 실제 송출까지 검증했다고 보고하지 마.
구현·빌드·실제 실행 검증까지 진행하고 변경 파일, 확인한 원인, 전후 성공률·첫 이미지 시간·재시도·CPU/GPU/메모리, 미검증 조건과 남은 제약을 보고해. 대기시간이나 실패 문구만 바꾼 것을 개선 완료로 처리하지 마.
